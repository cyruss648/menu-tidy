# Menu Tidy

一个使用 SwiftUI 与 AppKit 开发的 macOS 菜单栏整理工具。在列表中设置分类；macOS 27 通过明确对应的系统排序记录调整并隐藏图标，再由菜单栏下方的独立图标栏显示原始图标快照。也保留用户主动按住 ⌘ 拖拽分组的入口。

[下载发布版本](https://github.com/cyruss648/menu-tidy/releases) · [使用与开发文档](docs/README.md) · [反馈问题](https://github.com/cyruss648/menu-tidy/issues)

> **当前开发版：0.5.0，开发中，尚未发布。** 正常功能不移动用户鼠标，也不发送全局模拟键鼠事件；采集图像和点击隐藏项时，会通过系统排序记录临时显示单个图标。后台分类、图标操作及应用内更新仍在验证兼容性，最新结果与限制见[开发验证记录](docs/ICON-PANEL-VERIFICATION.md)。

## 主要功能

- 在列表中搜索应用，将图标分为三类；修改先保留为草稿，点击「应用并收起」后尝试后台调整，只有实际分类通过验证才保存。
- 进入「在菜单栏拖拽分组」前，条件恢复本应用管理的隐藏项原排序；按住 ⌘ 使用 macOS 原生拖动，完成后根据边界确认分类，macOS 27 再应用并验证后台隐藏。
- 点击菜单栏「···」打开下方图标栏；打开时按钮变为向上箭头（⌃），再次点击收起。右键打开管理菜单。
- 图标栏显示原始菜单栏图标的快照；点击外部、切换到其他窗口或按 Esc 收起，仅查看图标栏时不需要展开整条原生菜单栏。
- 点击受管理的隐藏图标时，先临时显示该单项并确认可见，再向原始辅助功能对象发送一次后台动作；确认目标菜单或窗口打开后等待其关闭，再恢复隐藏，不补发模拟点击。
- 「临时显示全部」在同一个图标栏中加入「始终隐藏」项目，不自动打开管理窗口。
- 保存具备稳定标识的图标规则；支持自动收起、启动时收起和登录启动设置，默认均关闭。
- 管理窗口打开时显示 Dock 图标；关闭管理窗口后回到菜单栏运行。最小化或隐藏窗口会保留 Dock 图标，方便再次打开。
- 管理列表使用系统应用图标；独立图标栏另需屏幕录制权限，快照只保存在内存中。
- 开发版新增应用内更新，设置与菜单共享更新状态；默认自动检查，自动下载并在退出时安装默认关闭。

下表描述分类已经验证生效后的行为；待应用选择不代表图标已隐藏。macOS 27 使用逐项位置记录隐藏，打开下方图标栏不会展开全部原生项目；旧系统使用分隔项分区。原生菜单栏的位置调整仍受系统可用空间限制。

| 分类 | 原生菜单栏收起时 | 独立图标栏打开时 |
| --- | --- | --- |
| 常驻显示 | 本应用不主动隐藏 | 继续留在原生菜单栏 |
| 收起后隐藏 | 保持隐藏 | 显示已采集的原始图标 |
| 始终隐藏 | 保持隐藏 | 普通打开不显示，可通过「临时显示全部」查看 |

## 安装

应用最低部署目标为 **macOS 13**；独立图标窗口捕获需要 macOS 14+，原始图标区域快照需要 **macOS 15.2 或更新版本**。macOS 27 使用区域快照兼容路径。最低部署目标不表示旧系统具备完整的独立图标栏功能，也不代表已完成这些系统的交互验收。架构、签名、公证状态和预发布标记以 [Release 说明](https://github.com/cyruss648/menu-tidy/releases) 为准。

GitHub 发布提供 Apple Silicon（`arm64`）与 Intel（`x86_64`）独立安装包。**现有公开版本以 Release 标记为准；0.5.0 尚未发布。安装包使用项目专用自签名证书，并非 Apple Developer ID，尚未公证。**

1. 下载与 Mac 架构对应的发布包，解压得到 `Menu Tidy.app`。
2. 将应用放入 **应用程序**文件夹后打开，避免从临时解压目录反复启动不同副本。
3. 首次升级到包含更新器的版本仍需手动安装：先退出旧实例，再替换应用。后续可从应用内检查更新，也保留手动下载安装方式。签名身份或安装位置变化后，macOS 可能要求重新授权。

如果系统阻止首次打开，请先核对下载来源与 Release 的签名说明，再使用 macOS 提供的允许打开入口。不要关闭系统安全保护来绕过提示。

## 软件更新

包含更新器的版本可在设置的更新区域或菜单中选择 **检查更新…**。默认开启自动检查，但不会默认自动下载并在退出时安装；是否开启后者由用户选择。关闭自动检查会暂停自动检查和下载，手动检查仍可用；不能将其视为取消已经排定的安装。两处入口使用同一个更新器，显示当前版本、最近检查时间和更新状态。正在整理、应用分类或恢复排序时，更新操作会等待或提示稍后再试。

每个安装包固定使用对应架构和版本通道：不带预发布后缀的版本使用 `stable`，例如 `0.5.0`；带后缀的版本使用 `preview`，例如 `0.5.0-beta.1`。当前没有通道切换开关，也不会因文档写着“开发版”而自动改为预览通道。下载包与更新 feed 都要求签名验证。

**没有「软件更新」入口的旧版，首次需要手动下载安装包含更新器的版本。** 此功能尚未正式发布，当前没有公开的新更新 feed；正式发布后的新版本可按上述方式更新。配置、发布流程与验证范围详见[应用内更新说明](docs/AUTO-UPDATE.md)。

## 开始使用

1. 先退出 Barbee、Bartender、Ice 等其他菜单栏整理器。
2. 在 Menu Tidy 中点击 **申请辅助功能权限**，按系统提示开启当前安装副本的权限。
3. macOS 27 的后台分类还需点击 **授权排序目录…**。在系统选择器中确认已定位的 `~/Library/Group Containers/com.apple.MenuBar/Library/Preferences` 目录；应用检测能否读取其中的菜单栏排序记录，并记住这项授权。请选择该目录，不需要授权整个磁盘。
4. 要使用下方图标栏，在 **权限与设置** 中申请屏幕录制权限，并在系统设置中开启当前 Menu Tidy 副本。
5. 返回应用，等待自动检测；也可点击 **重新检测**。启动和刷新会读取现有菜单栏，已授权屏幕录制时只采集身份及可见位置确认的图标。应用后台隐藏分类时，会将目标单项临时放到可见位置，采集图像后恢复隐藏；整个过程不移动用户鼠标。缺少图像时，也可关闭下方图标栏，手动展开系统溢出区并保持片刻，让应用在空闲时补采，无需切回设置。
6. 在列表中选择分类并点击 **应用并收起**。macOS 27 核对目标与既有排序记录的对应关系，保存恢复记录后调整位置，再验证实际可见或隐藏状态；其他系统仅尝试受支持的后台路径。不支持或未确认成功的项目继续保留为待应用草稿。也可自主使用下面的 **在菜单栏拖拽分组**。
7. 日常点击「···」查看下方图标栏。要修改分组，右键打开管理界面；关闭管理窗口不会退出应用。

### 在菜单栏拖拽分组

1. 右键点击菜单栏「···」，选择 **在菜单栏拖拽分组**（管理界面也提供入口）。macOS 27 先恢复本应用仍在管理的隐藏项原排序；若恢复不完整，会保留记录并提示处理，不直接开始拖拽。随后显示「常隐」「收起」两个标记；原生空间不足的项目仍可能位于系统溢出区。
2. 按住 **⌘ Command**，直接拖动菜单栏中的图标。分组取决于图标与两个标记的相对位置：

   | 图标位置 | 对应分组 |
   | --- | --- |
   | 「常隐」左侧 | 始终隐藏 |
   | 「常隐」与「收起」之间 | 收起后隐藏 |
   | 「收起」右侧 | 常驻显示 |

3. 松开 ⌘ 和鼠标，点击 **完成并收起**；也可点击菜单栏「···」或从其右键菜单完成。应用先用连续两次可信扫描确认边界分类；macOS 27 随后通过后台排序记录逐项隐藏并验证，未确认生效的项目仍标为待应用。未知位置不会被猜测为某一组。

macOS 27 的两个标记用于确认用户拖动后的分类，实际隐藏由逐项后台记录完成；旧系统继续按标记位置收起分区。已确认的「始终隐藏」项目不会出现在普通图标栏中。整理期间暂停列表分类、应用并收起和临时显示操作。选择 **保持展开并退出** 会保留已拖动的位置，退出整理而不重新应用后台隐藏，不会撤销拖动。

### 临时查看隐藏项目

点击「···」打开下方图标栏，默认仅显示「收起后隐藏」项目。从右键菜单选择 **临时显示全部**，会在图标栏中加入「始终隐藏」项目，**不自动打开管理窗口，也不展开全部原生图标**。再次点击向上箭头、点击外部、切换窗口或按 Esc 可关闭图标栏。

图标栏显示原始菜单栏图案，去除能够可靠识别的截图底色，使黑白图标适配界面明暗，彩色图标保留颜色。在 macOS 27 上显示的是最近一次成功采集的快照，网络状态、计数、动画等不会在隐藏期间自动更新。需要更新时，在管理界面点击 **刷新图标**；macOS 27 会逐个临时显示由本应用托管的隐藏项，重新采集后恢复隐藏，不改变分类和待应用草稿。未在本轮完成的项目保留仍有效的旧快照，并提示原因。缺少可信快照的图标会显示占位符，不会用应用图标冒充原始菜单栏图像。图像是否取得与后台动作是否受支持是两项独立能力。

点击受管理的隐藏项目时，应用核对原始辅助功能对象、进程身份和排序记录，先将这一个图标临时放到 Menu Tidy 入口附近并确认可见，再记录展示基线，向原对象发送一次受支持的后台动作。确认目标菜单或窗口打开后，会等待该界面关闭，再把该项恢复到隐藏位置。此过程会调整图标位置，但不调用移动系统指针的 API，也不发送全局鼠标或键盘事件。接口返回成功不等于原生菜单已经打开。

若对象不支持后台动作、身份失效或菜单未被确认打开，应用会保留具体原因，不重复调用或改用模拟点击。某些图标的动作本来不打开菜单，因此“未确认新菜单”也不等于应用动作必定失败。原生菜单出现后按对应应用的方式使用和关闭；若已打开菜单的状态后来无法确认，项目可能暂时保持可见，并提供恢复提示。只有系统当前值仍符合本应用记录时才执行位置恢复，外部改动不会被强行覆盖。

「始终隐藏」不会退出对应应用，也不是隐私保护；手动打开系统溢出区仍可能看到这些图标。应用还提供 `Control + Option + M` 切换普通图标栏，以及 `Command + Return` 应用当前选择。

## 权限与常见限制

**辅助功能权限**用于读取菜单栏项目、核对身份与真实位置，以及查询和调用目标的后台动作，必须由用户在系统设置中开启。它不代表所有图标都提供这些接口。macOS 27 的相关页面可能显示为「设备控制和数据访问」。管理列表的应用图标来自应用文件。

**排序目录访问**用于 macOS 27 的后台分类、单项临时显示和位置恢复。它与辅助功能分开授权，通过应用内的系统文件选择器授予上述 Preferences 目录访问，无需完整磁盘访问权限。应用只调整已确认对应目标的既有排序记录，写入前保留原值和恢复记录；记录读回不等于分类已生效，仍需验证真实位置。若显示恢复提示，可选择 **重试恢复原排序**，或 **恢复隐藏项并保留外部改动**：后者先恢复仍由本应用管理的隐藏位置，再保留发生冲突的外部修改，不会把未完成的分类标成成功。

结束隐藏管理、进入原生拖拽整理或正常退出时，应用会条件恢复所管理项目的原记录。启动时也会处理未完成记录，不以辅助功能已授权作为恢复原值的前提；权限撤销后的恢复若受目录权限或外部改动阻止，会保留恢复提示。异常退出后仍需重新启动应用处理记录，不能保证进程未运行时立即恢复。

**屏幕录制权限**仅用于独立图标栏：优先采集系统提供的独立小图标窗口；系统没有提供时，只截取已确认图标所在的小矩形。不会采集整屏画面或声音，不上传、不写入磁盘。应用退出后快照即丢失；显示外观、缩放或屏幕布局变化后需要重新采集。撤销权限后无法继续使用图标栏。

如果系统开关已开、应用仍显示未授权，请在权限页展开「已开启仍未识别？」，按指引移除过期条目，再添加当前安装副本。持续本地开发可使用[固定本地签名身份](docs/LOCAL-SIGNING.md)减少身份变化。

- **目前仅扫描主显示器。** 快照采集也限于主显示器的菜单栏区域。
- **原生菜单栏空间不足仍会溢出。** 独立图标栏用于查看已采集的图标，不增加原生菜单栏容量。应用只通过受支持的后台动作尝试展开系统溢出入口；接口不支持或位置无法确认时会提示，不使用鼠标停驻或模拟点击。
- **macOS 27 当前使用缓存快照。** 系统未向当前实现提供独立的菜单图标实时窗口；隐藏状态下的图标不会实时刷新。快照可能与应用当前状态不同，实际操作以原生菜单为准。
- **顶部浮层可能遮挡图标。** 刘海面板、悬浮窗口和菜单可能使原始图标截图或展示确认失败。应用不会通过移动鼠标来绕开遮挡；需要时可收起浮层后刷新。
- **自动分类取决于严格的身份对应和真实布局。** 受保护项目不可分类；其他项目也可能无法唯一对应排序记录，或缺少可验证的位置证据。不能仅凭已保存的选择认定原生图标已隐藏，当前兼容性验证记录位于 docs。缺少唯一稳定标识的图标，其运行时规则不能按名称自动套到重启后的另一项目。
- **单项后台调用兼容性因应用而异。** 部分图标虽然提供了点击接口，实际调用仍返回不支持，例如当前验证的搜狗输入法；Clash Verge、FineTune 和天气菜单的后台调用则未确认新菜单或窗口。应用会明确提示当前结果，不会改用模拟鼠标；仍可从原生菜单栏手动使用对应图标，必要时手动展开系统溢出区。其他应用也可能缺少接口或不响应调用，不保证所有应用、旧系统、多显示器、全屏与睡眠恢复场景均可用。
- **错误会保留未完成选择。** 已验证的项目保存，其余保持待应用；未知几何和接口返回成功都不当作移动成功。明确选择会单独持久化为草稿。重启后，稳定标识按原 ID 恢复；没有稳定标识的项目保留为待关联草稿，需要在界面中明确关联，应用不会按同名图标自动套用。

更多使用说明与开发资料见[文档索引](docs/README.md)。后台操作的 API、实现边界与研究依据见[后台输入方案](docs/BACKGROUND-INPUT.md)。

## 用户数据

日常分类和偏好通常保存在 `~/Library/Preferences/dev.hdh.MenuTidy.plist`；后台位置事务与隐藏恢复记录保存在应用的 Application Support / Transactions 目录。原始图标快照只保留在内存中，退出后需要重新采集。删除应用不会自动删除偏好设置；应先正常退出并完成位置恢复，再处理卸载或数据清理。演示设置、系统权限以及开发机器上的测试和签名资料各有不同用途，详见[用户数据与存储位置](docs/USER-DATA.md)。

## 从源码开发

项目使用 Swift 6 与 Swift Package Manager，自更新依赖固定版本 **Sparkle 2.10.0**。在 macOS 上安装 Xcode 或 Command Line Tools、Python 3.11+、Git、`pre-commit` 和 `git-cliff` 后：

```sh
git clone https://github.com/cyruss648/menu-tidy.git
cd menu-tidy
./scripts/dev-setup.sh
./scripts/check.sh --full
./scripts/build.sh release
```

应用输出到 `dist/Menu Tidy.app`。`dev-setup.sh` 检查依赖并安装本仓库 Git hooks，不自动安装软件或创建签名证书。

开发安装、签名和提交约定见[开发指南](docs/DEVELOPMENT.md)，自动发布与签名配置见[发布指南](docs/RELEASING.md)，更新通道与签名 feed 见[应用内更新说明](docs/AUTO-UPDATE.md)。历史验收记录保留在 `docs/`，不会将构建通过替代功能验证。
