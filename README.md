# Menu Tidy

一个使用 SwiftUI 与 AppKit 开发的 macOS 菜单栏整理工具。选择 **常驻显示 / 收起后隐藏 / 始终隐藏** 后自动处理；日常点击菜单栏箭头，打开独立网格托盘并使用其中的图标。交互目标类似 Windows 的隐藏通知图标区，macOS 上的位置调整与原生菜单操作仍需逐项确认。

[下载发布版本](https://github.com/cyruss648/menu-tidy/releases) · [使用与开发文档](docs/README.md) · [反馈问题](https://github.com/cyruss648/menu-tidy/issues)

> **当前源码版本：0.6.2（构建 58），增加离线更新记录和 GitHub 入口；公开发布状态以 GitHub Release 为准。** 本文描述当前源码中的独立托盘实现，公开下载版本以 Release 为准。正常功能不移动用户鼠标，也不发送全局模拟键鼠事件；点击隐藏项时，可能先临时显示该单项，再请求原生后台动作。当前设计、实机证据与未验证边界见[独立托盘体验](docs/TRAY-EXPERIENCE.md)。

## 主要功能

- 每个图标提供 **常驻显示 / 收起后隐藏 / 始终隐藏** 三项选择，更改后立即保存并处理。待应用、处理中和错误分别显示；顶部固定提供 **应用全部待处理** 和 **重试失败项**，可一次继续处理多个项目。
- 快速来回切换同一项时保留最新意图；实际位置操作串行执行，只有真实位置验证通过才保存为已完成。失败或取消不会在后台反复重试。
- 点击菜单栏箭头立即展示已知托盘项目，使用六列独立网格；项目较多时纵向滚动。查看托盘不等待全量扫描、截图采集或整批位置调整。
- 优先显示有效的原始图标缓存；缺图时显示标明来源的应用图标或名称标识。屏幕录制是可选的原图外观增强，不是打开托盘的前提。
- 左键请求目标原始辅助功能对象的一次原生动作；确认原生菜单或窗口出现后让用户继续使用，关闭后恢复隐藏。右键显示 Menu Tidy 自己的 **打开菜单 / 常驻菜单栏** 操作。
- 启动及发现应用新进程时，对已保存规则尝试一次重新连接。普通刷新不会重复重试同一进程已失败的设置；用户的新选择优先于自动连接工作。
- 原高级维护的分类、刷新与批量操作已并入同一列表；离线规则与待关联草稿在 **离线与保留记录** 中折叠保留。图像重采和临时显示全部位于列表的更多菜单，恢复提示仍直接显示。
- 支持自动收起、启动时收起和登录启动设置，默认均关闭。
- 管理窗口打开时显示 Dock 图标；关闭管理窗口后回到菜单栏运行。最小化或隐藏窗口会保留 Dock 图标，方便再次打开。
- 原始图标快照只保存在内存中；应用身份图标来自本机应用文件。
- 开发版新增应用内更新，设置与菜单共享更新状态；默认自动检查，自动下载并在退出时安装默认关闭。

下表描述位置已经验证完成后的行为。处理中或待确认的选择不代表原生图标已经改变；顶部数量按当前选择统计。macOS 27 使用按应用控制的原生显示开关；日常模式只保留托盘按钮，两个宽占位不再显示。打开独立托盘不会展开全部原生项目。支持范围与实机证据见[原生隐藏验证](docs/NATIVE-VISIBILITY-RESEARCH.md)。

| 去向 | 原生菜单栏 | 独立托盘 |
| --- | --- | --- |
| 常驻显示 | 本应用不主动隐藏；仍受系统可用空间限制 | 不作为托盘隐藏项展示 |
| 收起后隐藏 | 保持隐藏 | 点击箭头时展示原始图标缓存或应用身份图标 |
| 始终隐藏 | 保持隐藏 | 普通打开不展示；“临时显示全部”时可见 |

托盘展示的是 Menu Tidy 的代理入口，**没有将第三方原生 `NSStatusItem` 控件搬进自己的窗口**。缓存能显示不代表目标的原生后台动作一定受支持；该能力按项目验证。

## 安装

应用最低部署目标为 **macOS 13**；独立图标窗口捕获需要 macOS 14+，原始图标区域快照需要 **macOS 15.2 或更新版本**。macOS 27 使用区域快照兼容路径；原图获取不可用时，托盘可以显示应用身份图标。最低部署目标不表示旧系统上的隐藏、恢复和原生菜单操作已完成交互验收。架构、签名、公证状态和预发布标记以 [Release 说明](https://github.com/cyruss648/menu-tidy/releases) 为准。

GitHub 发布提供 Apple Silicon（`arm64`）与 Intel（`x86_64`）独立安装包。**可下载版本与构建状态以 Release 标记为准。安装包使用项目专用自签名证书，并非 Apple Developer ID，尚未公证。**

1. 下载与 Mac 架构对应的发布包，解压得到 `Menu Tidy.app`。
2. 将应用放入 **应用程序**文件夹后打开，避免从临时解压目录反复启动不同副本。
3. 首次升级到包含更新器的版本仍需手动安装：先退出旧实例，再替换应用。后续可从应用内检查更新，也保留手动下载安装方式。签名身份或安装位置变化后，macOS 可能要求重新授权。

如果系统阻止首次打开，请先核对下载来源与 Release 的签名说明，再使用 macOS 提供的允许打开入口。不要关闭系统安全保护来绕过提示。

## 软件更新

包含更新器的版本可在设置的更新区域或菜单中选择 **检查更新…**。默认开启自动检查，但不会默认自动下载并在退出时安装；是否开启后者由用户选择。关闭自动检查会暂停自动检查和下载，手动检查仍可用；不能将其视为取消已经排定的安装。两处入口使用同一个更新器，显示当前版本、最近检查时间和更新状态。正在整理、应用分类或恢复排序时，更新操作会等待或提示稍后再试。

每个安装包固定使用对应架构和版本通道：不带预发布后缀的版本使用 `stable`，例如 `0.5.0`；带后缀的版本使用 `preview`，例如 `0.5.0-beta.1`。当前没有通道切换开关，也不会因文档写着“开发版”而自动改为预览通道。下载包与更新 feed 都要求签名验证。

**没有「软件更新」入口的旧版，首次需要手动下载安装包含更新器的版本。** 0.5.0 包含更新器，签名更新 feed 随成功发布生成；后续新版本可按上述方式更新。配置、发布流程与验证范围详见[应用内更新说明](docs/AUTO-UPDATE.md)。

## 开始使用

1. 先退出 Barbee、Bartender、Ice 等其他菜单栏整理器，避免同时调整图标。
2. 在 Menu Tidy 中点击 **申请辅助功能权限**，按系统提示开启当前安装副本的权限。
3. macOS 27 还需点击 **授权菜单栏显示设置…**，在系统选择器中确认已定位的 `group.com.apple.controlcenter.plist` 文件。旧版本遗留的位置恢复可能另需原排序目录授权；先完成旧恢复，再启用新隐藏方式。无需完整磁盘访问。
4. 在 **托盘图标** 页找到应用，选择 **常驻显示 / 收起后隐藏 / 始终隐藏**。选择立即进入单项处理，行内显示进度；可以继续设置其他项或再次改变同一项的选择。
5. 点击菜单栏箭头打开独立托盘，再点击需要使用的图标。再次点击箭头、点击外部、切换窗口或按 **Esc** 可收起托盘。管理窗口关闭后，应用继续在菜单栏运行。
6. 若希望显示原始菜单栏图案，可在 **权限与设置 → 增强托盘图标外观（可选）** 中申请屏幕录制权限。未开启或尚无可信原图时，托盘仍使用应用身份图标或名称标识，不会把它们标作原始图标。

某项未完成时，在对应行查看原因并点击 **应用** 或 **重试**。顶部 **应用全部待处理** 处理所有可直接应用的未完成选择，**重试失败项** 仅处理失败项；不受搜索与筛选影响，跳过已确认、离线、保护和需要单独识别的项目。身份需要确认时使用行内 **识别并连接**。主页面的 **需要处理** 筛选可以集中查看这些项目。后台保存用户意图不等于位置已经成功改变，只有真实位置验证通过才确认完成。

原生显示开关按应用生效，同一应用的多个图标共用常驻或托盘选择，不依赖旧系统排序表中的编号。旧位置记录不需要删除。对归属不明确或尚未支持的系统图标，界面保留当前状态并显示原因。

启动以及发现新的应用进程时，会对已保存规则进行一次自动重新连接。失败或取消后不会反复后台重试；普通刷新也不会把同一进程已失败的设置再执行一遍。需要继续时由你明确重试。新进程的首次发现与普通读取已有项目的状态是两种情况。

### 使用独立托盘

托盘采用六列网格，首帧直接使用已知项目、有效原图缓存或应用身份图标，项目较多时纵向滚动。打开面板与实际操作原生图标是两条路径：面板可以很快出现，原生菜单仍需要核对当前身份、位置与系统响应，不能据此承诺每次操作都瞬间完成。

**左键**会请求打开目标的原生菜单或窗口。对于受管理的隐藏项，应用先临时显示该项并确认可见，向原始辅助功能对象发送一次受支持的后台动作；确认原生界面打开后让用户使用，关闭后恢复隐藏。动作无法确认时给出该项原因，不重复发送，不改用全局模拟点击。原生界面可能出现在系统确定的位置，并非从代理图像中迁出的控件。

**右键**显示的是 Menu Tidy 自己的上下文菜单，可选择 **打开菜单** 或 **常驻菜单栏**。它不承诺转发第三方图标的右键事件，也不等同于第三方应用的原生右键菜单。

原始图标是最近一次成功采集的快照，隐藏时的计数、动画或网络状态可能不会同步更新；实际状态以打开后的原生界面为准。图像是否取得与原生后台动作是否受支持是两项独立能力。`Control + Option + M` 可切换独立托盘。

### 统一管理与保留记录

三项选择、搜索筛选、刷新与批量按钮使用同一份状态，不再显示重复的高级分类列表。三张概览卡按当前在线图标的选择统计，点击可筛选；未完成数与成功结果分开。

**离线与保留记录** 不参加批量操作。旧会话草稿需要明确关联当前图标，关联后保留为待应用，不立即改变菜单栏。原生模式下 **忘记此应用…** 会先说明删除范围：仅当应用没有可用图标时，删除它的离线规则、分类选择及草稿，保留其他应用记录和所有恢复账本。

**刷新列表**（⌘R）重新读取项目与状态；对同一进程已经尝试过的规则，不隐式重复应用。**更新图标栏图像**是独立维护动作，可逐项临时显示受管理的隐藏项、采集并恢复，不以截图成功替代位置验证，也不修改分类意图。未获得原图不妨碍托盘显示应用身份入口。

保留的 **在菜单栏拖拽分组** 使用 macOS 原生 ⌘ 拖动：进入前先条件恢复本应用管理的隐藏位置；“常隐”左侧为旧版始终隐藏，“常隐”与“收起”之间为收起后隐藏，“收起”右侧为常驻。完成后读取分组并验证后台隐藏；未知位置不会被猜测。**保持展开并退出** 保留用户已经拖动的位置，不撤销拖动。

macOS 27 原生隐藏模式不再显示宽占位和拖拽分组入口；旧系统兼容模式仍保留原生拖拽。移除占位可消除本应用造成的菜单栏拥挤；若用户保留的常驻图标自身超出屏幕空间，macOS 仍可能显示系统溢出入口。

有 **停止** 入口的操作可点击该按钮或按 **Esc** 停止后续工作。若已经临时调整位置，应用先完成必要恢复，恢复结束前不开始冲突写入。正常工作阶段有时间预算，恢复独立等待，界面用时不是硬实时完成承诺。恢复未完成时会保留记录和主页面恢复入口，不把操作显示成已成功。

## 权限与常见限制

**辅助功能权限**用于读取菜单栏项目、核对身份与真实位置，以及查询和调用目标的后台动作，必须由用户在系统设置中开启。它不代表所有图标都提供这些接口。macOS 27 的相关页面可能显示为「设备控制和数据访问」。管理列表的应用图标来自应用文件。

**菜单栏显示设置文件访问**用于 macOS 27 的原生隐藏、临时显示和恢复，通过系统文件选择器只授权精确偏好文件。已验证的系统模块可能另需该模块的精确文件访问。**排序目录访问**仅用于旧位置恢复或兼容路径，两者都无需完整磁盘访问。写入前保留恢复意图，读回与真实显示分别验证；恢复只处理仍属于本应用的修改。恢复提示提供 **重试恢复图标**，或 **恢复隐藏项并保留外部改动**；无法安全确认的恢复记录继续保留，未完成选择不会标为成功。

结束隐藏管理、进入原生拖拽整理或正常退出时，应用会条件恢复所管理项目的原记录。启动时也会处理未完成记录，不以辅助功能已授权作为恢复原值的前提；权限撤销后的恢复若受目录权限或外部改动阻止，会保留恢复提示。异常退出后仍需重新启动应用处理记录，不能保证进程未运行时立即恢复。

**屏幕录制权限是可选增强**：优先采集系统提供的独立小图标窗口；系统没有提供时，只截取已确认图标所在的小矩形。不会采集整屏画面或声音，不上传、不写入磁盘。应用退出后快照即丢失；显示外观、缩放或屏幕布局变化后需要重新采集。未授予或撤销权限后，托盘改用应用身份图标或名称标识；这不会提供目标本来缺少的后台操作能力。

如果系统开关已开、应用仍显示未授权，请在权限页展开「已开启仍未识别？」，按指引移除过期条目，再添加当前安装副本。持续本地开发可使用[固定本地签名身份](docs/LOCAL-SIGNING.md)减少身份变化。

- **目前仅扫描主显示器。** 快照采集也限于主显示器的菜单栏区域。
- **原生菜单栏空间不足仍会溢出。** 独立托盘不会增加原生菜单栏容量。常驻项及原生菜单的展示仍受系统布局限制；接口不支持或位置无法确认时会提示，不使用鼠标停驻或全局模拟点击。
- **macOS 27 当前使用缓存快照。** 系统未向当前实现提供独立的菜单图标实时窗口；隐藏状态下的图标不会实时刷新。快照可能与应用当前状态不同，实际操作以原生菜单为准。
- **顶部浮层可能遮挡图标。** 刘海面板、悬浮窗口和菜单可能使原始图标截图或展示确认失败。应用不会通过移动鼠标来绕开遮挡；需要时可收起浮层后刷新。
- **自动分类取决于严格的身份对应和真实布局。** 受保护项目不可分类；其他项目也可能无法唯一对应排序记录，或缺少可验证的位置证据。不能仅凭已保存的选择认定原生图标已隐藏，当前兼容性验证记录位于 docs。缺少唯一稳定标识的图标，其运行时规则不能按名称自动套到重启后的另一项目。
- **单项后台调用兼容性因应用而异。** 当前独立托盘候选已确认 AirDrop 的原生界面打开与关闭后恢复隐藏。此前版本记录过搜狗输入法动作不支持，以及 Clash Verge、FineTune、天气菜单未确认新界面等情况；这些是对应候选的历史结果，不能作为新候选的全面兼容结论。应用会提示当前结果，必要时可恢复为常驻后从原生菜单栏使用。不保证所有应用、旧系统、多显示器、全屏与睡眠恢复场景均可用。
- **错误会保留未完成选择。** 用户意图先持久化，真实位置确认后才成为已完成规则；未知几何和接口返回成功都不当作成功。单项失败局部提示，失败或取消不后台重试。稳定标识可恢复原 ID；没有稳定标识的旧记录保留在离线与保留记录中等待明确关联，不按同名图标自动套用。

本次融合改进及验证边界见[统一管理页评审](docs/UNIFIED-MANAGEMENT.md)。当前交互合同与历史实机证据见[独立托盘体验](docs/TRAY-EXPERIENCE.md)，其他资料见[文档索引](docs/README.md)。[后台输入方案](docs/BACKGROUND-INPUT.md)与[交互与执行流程评审](docs/INTERACTION-REVIEW.md)保留此前实现的技术依据和验收记录；涉及主界面、图像权限及日常操作的旧合同由当前托盘文档补充。

## 用户数据

日常分类和偏好通常保存在 `~/Library/Preferences/dev.hdh.MenuTidy.plist`；后台位置事务与隐藏恢复记录保存在应用的 Application Support / Transactions 目录。原始图标快照只保留在内存中，退出后需要重新采集。删除应用不会自动删除偏好设置；应先正常退出并完成位置恢复，再处理卸载或数据清理。演示设置、系统权限以及开发机器上的测试和签名资料各有不同用途，详见[用户数据与存储位置](docs/USER-DATA.md)。

## 从源码开发

项目使用 Swift 6 与 Swift Package Manager，自更新依赖固定版本 **Sparkle 2.10.0**。在 macOS 上安装 Xcode 或 Command Line Tools、Python 3.11+、Git、`pre-commit` 和 `git-cliff` 后：

```sh
git clone https://github.com/cyruss648/menu-tidy.git
cd menu-tidy
./scripts/dev-setup.sh
./scripts/check.sh --full
./scripts/build.sh release
```
