# 独立托盘：功能、设计与验收

当前目标是类似 Windows 隐藏通知图标区的日常体验：常用项目留在菜单栏，其余放进箭头下方的独立托盘，打开后直接选择应用。主流程只有 **常驻菜单栏 / 收进托盘** 两种去向，选择后自动执行单项设置，不要求用户管理草稿或点击批量应用。

本文对应 0.5.0 的实现；本地候选与 GitHub 发布包的验收分别记录。它补充并更新[上一阶段交互评审](INTERACTION-REVIEW.md)中的主界面、启动连接、图像权限与日常操作合同；历史文档和历史验证结果保留，不改写成当前候选已经完成的验收。

## 实现边界

独立托盘是 Menu Tidy 自己的窗口和代理入口，不是把其他应用的原生 `NSStatusItem` 移入本应用。macOS 27 的普通应用隐藏与临时显示通过精确应用的原生显示开关实现；系统模块采用逐项验证的单独通道。日常模式移除宽占位，只保留托盘按钮。打开目标请求当前身份核实后的原始辅助功能对象提供的后台动作。

因此，三个结果需要分别确认：托盘是否立即可见、原生图标是否确实隐藏或恢复、点击是否真正打开目标原生界面。显示缓存、写入设置、AX 接口返回成功，都不能单独替代另外两项证明。

## 用户操作合同

| 操作 | 当前行为 | 完成或异常提示 |
| --- | --- | --- |
| 选择“收进托盘” | 保存最新意图，排入该项的原生位置操作 | 行内显示处理中；真实隐藏验证通过后确认完成 |
| 选择“常驻菜单栏” | 排入该项的原生位置恢复 | 真实可见位置确认后完成；失败保留原因与重试入口 |
| 快速反复切换同一项 | 合并为最新意图，旧任务的完成不能消费新选择 | 不积累过时的重复动作；界面继续显示最新选择 |
| 点击菜单栏箭头 | 使用已知项目和本地缓存立即创建六列网格；较多项目纵向滚动 | 不等待全量扫描、截图重采或整批写入后才显示面板 |
| 左键托盘项目 | 针对原始对象请求一次后台动作；必要时先临时显示该单项 | 真正确认原生菜单或窗口出现后交给用户使用；失败在局部显示原因 |
| 右键托盘项目 | 显示 Menu Tidy 的“打开菜单 / 常驻菜单栏”菜单 | 不承诺转发第三方右键事件，不冒充第三方原生右键菜单 |
| 原生菜单关闭 | 条件恢复本应用临时修改的位置并验证 | 恢复未完成则保留记录和明确的恢复入口 |
| 再次点击箭头、点击外部或 Esc | 关闭独立托盘 | 不将关闭面板等同于取消已经发生的原生动作 |

顶部统计按当前选择计算，包含处理中的最新意图，不能解释为已成功隐藏数量。主列表显示应用身份图标、名称、去向以及本项状态；需要处理的项目可以筛选并明确重试。旧规则尚未重新确认时也会提示，不能把已保存偏好当作当前原生状态。

在后台读取列表或调整某项期间，用户仍可打开托盘、查看项目和改变其他项的选择。实际原生写入保持串行；恢复未完成、正在原生拖拽整理等冲突阶段仍会暂缓有关动作。独立面板首帧很快出现，并不表示所有原生操作都能瞬间完成。

## 状态与执行方式

### 用户意图与已完成规则分开

1. 单项选择先保存用户意图；界面立即反映最新目标去向并显示处理中。
2. 同一项目重复选择合并为最新意图。原生位置操作按队列串行进行，不允许旧任务的回调覆盖较新的选择。
3. 开始该项操作前检查权限、当前对象身份、原生显示记录及恢复状态。
4. 执行必要改动并验证实际可见性；只有验证通过，才能提交已完成规则并消除相应未完成记录。
5. 失败与取消停止该次尝试，显示本项原因，保留必要恢复信息。不会因为定时刷新而不停重试，也不会为获取更好看的截图而否定已经确认的位置结果。

内部仍使用待处理记录、确认规则和恢复账本，这是保证重启和中断后可恢复的实现细节。主界面不要求用户先创建草稿再批量应用。

### 自动重新连接

启动和发现应用新进程时，对相应的已保存规则尝试一次重新连接。进程身份包含运行实例信息，不能只按应用名称套用到其他对象。用户新意图优先进入原生串行队列。

同一进程已经失败或取消的设置，不由普通刷新反复重试；用户可以在该项明确重试。普通刷新读到一个新运行实例时，新实例的首次连接属于上述发现策略，不能与“刷新重试旧失败”混为一谈。离线、身份不稳定或需要明确关联的旧记录保留，不猜测对应关系。

### 独立托盘与图像

托盘为六列网格，先同步提供可用内容，再进行可选的图像更新。显示顺序为：身份匹配的有效原始图标缓存 → 应用身份图标 → 名称标识。替代图标有来源说明，不宣称它们是原始菜单栏图案。

屏幕录制权限仅增强原始图标外观。未授权、撤销授权或没有可信原图时，托盘仍可显示应用身份入口；它不会因此获得目标本来不支持的后台动作。原图只留在内存中，不上传、不写入磁盘。隐藏期间的计数、动画和网络状态可能落后于应用实际状态，打开后的原生界面才是使用依据。

原生动作调用时，托盘会让出可能遮挡系统菜单的窗口层级。失败、恢复和用户关闭的处理保留本次展示身份，防止过期回调重新弹出已经被用户关闭的面板。不会把一次 AX 请求反复补发成多个点击。

## 高级维护与数据延续

**高级兼容维护** 保留旧三分组、离线草稿关联、批量应用、列表读取和原图采集；原生 ⌘ 拖拽入口仅用于旧系统兼容模式。历史“收起后隐藏”和“始终隐藏”的隐藏项目都纳入当前日常托盘；旧分类记录本身保留，不能仅为简化界面删除恢复账本。

普通用户使用两种去向即可。图像重采和批量旧规则处理是独立维护动作；屏幕图像获取失败不会把已确认的位置修改变成失败。权限缺失和需要恢复的位置仍在主界面提供必要入口，不藏在高级面板中。

对系统值的恢复遵循原有条件：仅在当前值仍与本应用记录相符时恢复，避免覆盖其他操作产生的布局。正常工作阶段的时间预算与必要恢复分开，停止请求也必须等待已开始的临时修改安全结束。

## AutoFocus 多位置记录修复（2026-09-27 后续候选）

本节记录上述候选之后的修复，不把此前 AutoFocus 的失败记录改成成功。系统中存在 `status:com.mantel.AutoFocus::Item-0` 与 `Item-1` 两条位置记录，这表示原实现无法静态唯一匹配当前图标；不能据此判断安装了两个应用，也不能认定其中一条必然是可删除的历史残留。

此前重构移除了批量流程中的自动位置识别，却遗漏了单项显式识别入口。本次将已有的双向位置验证接回 **识别并连接**：只在用户明确重试该项时执行，检查原始辅助功能对象、进程实例和候选记录集合；同一对象必须在定位项两侧各取得连续的真实命中，探测修改全部恢复后才接受对应关系。启动、普通刷新和普通批量应用不自动进入这一过程。正常识别和应用共用单项时间预算，必要恢复独立完成。

识别请求作为队列中的独立意图保存。较新的普通选择会撤销尚未开始的识别请求；其他项目不会继承识别标志，旧完成回调也不能删除新意图。新增 6 项队列测试覆盖这些行为，原有 18 项位置识别测试继续检查双侧观察、身份变化、候选变化与恢复要求。

对应关系只保留在当前运行实例的内存中，绑定原始辅助功能对象和进程启动时间，不保存成下次启动可直接套用的永久映射。Menu Tidy 或 AutoFocus 重启后，若依然存在歧义，需要重新识别；未识别的记录不删除。
