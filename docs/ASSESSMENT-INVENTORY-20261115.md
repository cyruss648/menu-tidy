# 原生隐藏后的托盘清单保留

## 结论与现场证据

2026-11-15 在 macOS 27.2.1、0.7.23（99）上复现：管理窗口有多个运行中应用显示“系统保留”，托盘实际仅有搜狗输入法、BLEUnlock、MenuPiP、TextInputMenuAgent 和 WhatCable 五项。Atoll、Bob、Clash Verge、InputLock、JetBrains Toolbox 等进程仍在运行，问题不能归因于这些应用未启动。

启动日志在释放 assessment 后读到 19 个 host bindings。12:46:30 重新执行隐藏后，后续扫描中的 bindings 从 12、10、8 逐步降到 5。原生隐藏会移除源 AX 节点，但扫描只向已经存在 `NativeVisibilityEvidence` 的节点提供保留机会；启动意图可在确认前先隐藏应用。模型又丢弃已扫描但未返回的旧快照，因此隐藏成功反而删除了托盘入口。之前仅延长启动发现重试，不能覆盖此路径。

管理窗口把缺少源节点的普通应用降为 `canMove=false`，随后统一标成“系统保留”，并从未完成计数中排除，掩盖了清单丢失。

## 修复约束

- assessment 的应用级管理权与 AX 节点生命周期分开。已经观察到的应用在本进程管理的隐藏状态中失去全部源节点时，保留清单；严格要求 PID、bundle 和启动时间仍属于同一进程。
- 保留快照不提供当前几何证明，明确设为 `hasReliableGeometry=false`。打开原生菜单仍需临时显示、重新扫描并校验动作支持。
- 同一应用返回新源节点时，整体替换保留清单，避免叠加旧入口。进程退出、替换、取消管理、改成可见或临时显示时，不沿用这条保留路径。
- 只有当前已有同进程图标清单的保存应用才能进入 assessment 的隐藏意图，避免把尚未发现的应用先行隐藏。
- 运行中但尚未发现图标的应用使用独立的等待发现状态，并计入待确认与需要处理的数量；不授予其缺失的图标操作权限。

## 自动验证

本地完整门禁通过：Python 109、Core 532、App 164；App 中两项多屏测试因单屏环境跳过。新增两项集成回归覆盖确认前节点消失、连续刷新、同 PID 新启动时间不继承入口，以及新源替换旧清单。完整门禁不代表本机原生菜单验收通过。

## 桌面验收

发行签名测试流水线 `43679078809` 的双架构检查与打包通过，测试提交为 `1d5a00d35603b7cfa4d1f5959177ea047abe1816`。arm64 测试包通过归档与二进制摘要、EdDSA、公钥、架构、提交身份及 deep/strict 代码签名校验后，在本机运行。开发签名包未继承既有辅助功能授权，未修改系统权限来绕过这一边界。

实机结果：

- 首次启动并等待启动恢复完成后，托盘恢复为 20 个启用的入口，包含 Atoll、BLEUnlock、Bob、BobHelper、ChatGPT、Clash Verge、InputLock、JetBrains Toolbox、Mos 等；管理窗口仅剩邮箱大师等待发现。
- Atoll 和 BLEUnlock 的点击获得 `presentationConfirmed=true`，关闭后均获得 `nativeHiddenRestored=true`。Atoll 的外部 AX 只提供 notch 窗口，BLEUnlock 的外部 CUA 读取超时；这两项的菜单内部内容未另行遍历。
- Clash Verge 的默认打开应用路径实际打开窗口，获得 `windowConfirmed=true`。
- 正常退出后重启测试包，启动恢复完成后仍保留这些托盘入口。
- 邮箱大师另有独立原因：其偏好设置中“显示工具栏图标”未勾选，“开机自动运行网易邮箱大师”已勾选。开启图标显示后，Menu Tidy 发现并按原保存选择收进托盘。最终实际托盘为 21 个启用入口，管理窗口三组均无待确认项。
