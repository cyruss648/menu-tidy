# 0.6.5 回归验证

源码版本为 0.6.5（build 61），本轮针对代码与功能评审发现的四项问题修复，并补充直接运行应用模型的集成测试。公开发布状态以同版本 GitHub Release 与 Actions 为准。

## 修复范围

| 场景 | 预期行为 |
| --- | --- |
| 同应用旧分类混合，尚无应用级选择 | 自动连接保留原意图并显示需要统一选择；单项确认不绕过完整分类的一致性检查 |
| 用户明确统一同应用的类别 | 最新选择持久保存，兄弟图标使用相同类别，失败不自动反复重试 |
| 会话图标分类确认后，目标应用离线并重启 Menu Tidy | 仍能从离线记录查看及忘记应用级选择；忘记不影响其他应用和恢复记录 |
| 托盘操作耗时超过自动收起延迟，最后失败 | 操作期间不收起，恢复后获得完整等待时间，错误及重试入口可继续使用 |
| 新安装包删除旧版资源 | 整体替换应用，旧资源不残留，新包完整签名保持有效 |
| 复制、签名验证或替换失败 | 原安装保留或恢复；临时目录与备份有明确归属，不合并破损目录 |

## 自动化验证

`scripts/check.sh --full` 包含源码检查、Python 脚本回归、Swift warnings-as-errors 构建、Core 单元测试以及 `MenuTidyAppTests` 应用层集成测试。应用层测试直接调用真实 `MenuTidyModel` 的生产协调流程，替换系统读取与写入边界，并使用独立 UserDefaults，避免访问实际菜单栏和用户恢复账本。

2026-10-02 在 Apple Silicon macOS、Swift 6.4 上执行 `scripts/check.sh --full` 全部通过：489 项 Core 测试、12 项应用层集成测试和 96 项 Python 测试，Swift 构建与测试均启用 warnings-as-errors。12 项应用层测试包括 9 项分类与持久化集成场景，以及 3 项自动收起集成场景；96 项 Python 测试包括 16 项安装回归测试，实际使用签名临时应用核对整包替换和旧资源移除，并覆盖两次重命名成功后立即中断的回滚。

独立复审发现并补齐了“只有一个兄弟图标存在匹配草稿时的完整应用冲突判断”和“重命名已经成功但状态标记尚未更新时的中断恢复”，修复后的复审无剩余阻断项。

`swift build -c release -Xswiftc -warnings-as-errors` 也已通过，验证正式构建配置不依赖仅供调试的测试构造器。

## 证据边界

测试证明隔离输入下的状态衔接、持久化及失败恢复行为。它们不申请辅助功能权限，不修改用户菜单栏，不替换 `/Applications/Menu Tidy.app`，也不构成真实第三方图标动作、权限撤销、睡眠唤醒或多显示器切换的实机验收。Intel 与 Apple Silicon 的编译及自动化测试分别以对应发布工作流为准，不能由此推断 Intel 桌面交互或性能。

发布完成后，单独核验公开归档的 SHA-256、EdDSA、版本、构建号、架构、源码提交和签名身份，以及两个架构的 stable feed。产物核验、安装和真实运行是不同的证据；本轮只发布及核验，不更新本机已安装应用。
