# 资源占用与优化验证

2026-10-01 在 Apple M5 Pro、64 GiB 内存、macOS 27.0 上对已安装的 0.6.3（build 59）与发行身份签名的 0.6.4（build 60）候选版进行对照。本轮优化覆盖后台图像重试、界面状态发布、维护计时器、关闭窗口后的视图保留，以及应用身份图标缓存。

## 测量方法与结果

每种稳定状态使用 `top` 约每秒采样一次，排除首个预热样本后保留 60 个样本，实际窗口为 63–64 秒。CPU 百分比按单个逻辑核计量，100% 表示占满一个核，不是整机 CPU 的百分比。采样期间没有并行构建、测试、堆栈采样或堆分析。内存使用 `footprint` 的 `phys_footprint`；旧版设置页与后台栏使用 `top` 的取整内存数值，因此以“约”标注。

| 稳定状态 | 0.6.3 平均 CPU | 0.6.4 平均 CPU | 本轮 CPU 降幅 | 0.6.3 物理占用 | 0.6.4 物理占用 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 设置页打开、托盘收起 | 2.565% | 0.045% | 98.2% | 约 76–77 MiB | 76.05 MiB |
| 设置窗口关闭、托盘收起 | 0.385% | 0.038% | 90.0% | 约 81 MiB | 69.08 MiB |
| 托盘持续打开、使用缓存 | 9.808% | 0.165% | 98.3% | 81.80 MiB | 64.02 MiB |

托盘对照均包含 19 个项目、1 个已核验快照和其余应用身份图标。候选版重新启动后，通过一次可逆的显示、显式图像刷新、恢复隐藏操作准备相同的快照条件；操作后 `nativeTrayChoices.v1`、`itemRules.v1`、`itemDrafts.v1` 的解码数据与操作前完全一致。两个采样窗口开始和结束时托盘均保持打开，未把自动收起后的数据混入结果。根据进程累计 CPU 时间计算的托盘平均占用分别为 9.859% 与 0.222%，同样确认了明显下降。

设置窗口关闭后，生命周期事件在约 32 秒处确认 `releasedClosedSettingsContent`。同一候选进程在关闭前约 71.92 MiB，释放后约 69.08 MiB，下降 2.84 MiB；随后后台稳定采样的物理占用保持 69.08 MiB。设置页打开时内存没有明显下降，不能将优化概括为所有状态下内存均减少固定比例。

系统的临时菜单项目使读取到的列表在 27–28 项之间变化。新旧进程的启动时间和此前访问过的界面不同，因此表格属于本机短期观测，不能把跨进程的全部内存差异归因于某一个改动。原始采样、签名、偏好与安装回执保留在被 Git 忽略的 `.local/performance-20261001/`，不提交实际环境日志或偏好原件。

## 实现与保护边界

- 缺失图像使用单调时钟和 2 / 5 / 15 / 30 秒的重试间隔，无进展时逐步降频。应用启动或退出、唤醒、显示器变化、展开状态变化及明确刷新重启尝试预算；旧任务完成不能推迟新事件。候选集合为空时停止采集计时器；鼠标按下或取消时安排后续尝试，避免过期截止时间形成忙循环。
- 维护计时器按自动收起、权限检测、图像采集与待恢复工作中的最早截止时间安排一次唤醒；没有工作时停止。仍保留自动收起约 1 秒、设置页权限检测约 3 秒的检查间隔，并设置最多 1 秒的计时容差。
- 缓存托盘每 750 毫秒仍检查采集状态、权限、环境与进程生命周期，但图像对象、缓存状态及日期均相同时不发布重复界面数据，也不重复计算图像警告。列表按内容比较，常用行查询通过标识索引，并保持重复标识时原先“第一个匹配项”的展示语义。
- 设置窗口实际关闭 30 秒后释放 hosting tree；最小化或隐藏仍视为打开。小型独立状态对象保留页面、搜索、筛选与展开选择；内存压力时可以立即释放已关闭视图。
- 应用身份图标转换为 32 点的 2x 位图，LRU 同时限制 64 项与 1 MiB 位图成本，内存压力时清理可重建缓存。该限制不代表整个进程或系统共享图标服务的内存上限。仍有效的菜单栏快照、用户规则和恢复证据不作为此缓存的淘汰对象。

所有采集和原生操作仍核验权限、进程生命周期、目标身份、命中位置与采集后的几何证据；没有加入全局模拟输入或修改用户的恢复语义。

## 验证范围

本地 `scripts/check.sh --full` 通过源码门禁、80 项 Python 回归、Swift warnings-as-errors 构建与 489 项 Swift 测试。新增 8 项测试覆盖递增重试、事件与旧任务竞争、取消和进展重置、空任务停止、截止时间选择，以及 LRU 的条目/成本限制、替换、清理与整数溢出。

本机原生交互确认即时分类和恢复原分类、显式图像刷新、普通刷新、19 项缓存托盘持续打开、启用 15 秒自动收起后的关闭，以及设置视图释放后页面、搜索、筛选和详情/离线展开状态恢复。最小化事件保持 `windowOpen=true`，没有被当作窗口关闭。测试后恢复原有自动收起、启动收起和快捷键偏好；上述三份分类数据全部保留，待关联草稿为 0。

这里没有长期泄漏趋势、功耗/电池续航、持续实时图像更新、撤销系统权限、真实睡眠唤醒或显示器热插拔的实机证据。调度与保护边界的自动化测试不能替代这些情景。旧版系统与 Intel 桌面的实际交互和资源占用也没有实测；双架构编译与测试需查看对应版本的 GitHub Actions，不能当作 Intel 实机性能数据。
