# 状态展示与布局稳定性（2026-11-16）

## 问题与行为

打开管理窗口或后台读取图标时，原有“正在读取图标…”区域直接插入或移出正文；短任务频繁触发加载反馈，列表可见范围与滚动位置随之改变。行内失败说明、权限检查、软件更新反馈以及独立托盘错误区域也存在类似的条件布局。

0.7.26（build 102）采用以下展示规则：

- 活动持续 350 毫秒才显示进度；提前完成、视图关闭或任务被取消时撤销计时，后续操作重新计时。停止入口立即可用，不跟随提示延迟。
- 管理页底部保留 62 点状态栏。进度、完成结果和异常摘要在原位置更新；完整说明和恢复操作通过“状态详情”浮层查看。
- 行内说明保留两行空间，行内操作、批量数量和搜索清除按钮预留位置。权限检查及软件更新反馈保留固定空间。
- 图标列表使用普通 `VStack`，避免懒加载高度估算在刷新时改变文档高度；菜单栏清单规模有限。
- 托盘进度与错误复用既有底部栏，不增加窗口高度。错误详情可选择复制，保留重试入口；阅读浮层时暂停自动收起。
- 托盘详情锚点在错误消失时继续保留，关闭反馈在下一个主执行器周期发布，避免重试期间 SwiftUI 更新冲突。
- 软件更新区域观察语言偏好，切换语言后立即同步。
