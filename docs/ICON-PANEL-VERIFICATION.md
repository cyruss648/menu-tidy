## 平台观察与方案

2026-09-24，在 macOS 27 主显示器上查询 ScreenCaptureKit：系统没有暴露可与各菜单栏图标唯一对应的小窗口，不能在隐藏状态下取得独立窗口的实时画面。此结论来自该设备实际窗口元数据，不能外推到所有 macOS 版本。

兼容路径仅截取经过辅助功能位置、唯一性与命中验证的可见图标矩形，并在内存中缓存；隐藏状态使用这些原始快照。被其他窗口遮挡、几何不可靠、缺少缓存的项目不能拿应用图标冒充原始图像。权限撤销、来源进程更换及显示环境变化会使缓存失效。

## 上箭头重复切换

用户报告展开后点击向上箭头像触发两次。源码中存在竞态：失焦回调先将面板关闭，随后按钮 mouse-up 按当前状态切换，导致同一次点击重新展开。仅用按钮坐标排除失焦不足以处理远程菜单栏宿主的延迟事件。

修复采用持续存在的手势记录：按钮按下记录当时的展开状态，松开只执行对应的打开或关闭；关闭面板不删除在途按压记录。事件时间与面板代次用于隔离迟到回调；任何 mouse-down 都不能直接切换面板。键盘或辅助功能激活独立处理。

修复包完整静态检查、warnings-as-errors 构建与 74 项核心测试通过，其中 15 项为手势顺序与失焦回归。2026-09-24 03:26 安装固定证书构建，二进制 SHA-256 为 `fc629ccd6640512dc894378ac2c7fb5b0060939fd545fd08fb2c2a566d1919a6`。

在该安装包上，两轮通过 MenuBarAgent 辅助功能按钮执行的「展开 → 点击向上箭头」均保持收起。日志确认自动化点击没有鼠标事件，属于独立 AX 激活路径。**用户随后实际鼠标测试仍然失败，因此该包不能标记为修复完成。**

03:28 的物理点击记录确认了第二条路径：远程宿主的 control down 与 control up 动作时间仅相隔 1–4 微秒，down 时实际按钮仍按着；应用已经展开面板后，真正 physical up 约晚 100ms 到达，触发了 outside-dismiss。使用严格的 up 事件相等判定，无法把这两个不同时间的 up 归到同一次按压。

第二次修复以同一按钮最近一次 down 的时间界定当前手势，不再要求宿主 synthetic up 与真实 physical up 相等；新的 down 会立即开启下一次手势，因此不依靠固定 debounce。无匹配按下记录的物理 mouse-up 也不再误用独立 AX 的切换路径。

第二包静态检查、warnings-as-errors 构建与 **76 项测试**通过，新增 2 项覆盖远程宿主先产生 synthetic up、随后 physical up 的实际次序及下一次控制／外部点击。2026-09-24 03:32 已安装并启动，二进制 SHA-256：`795c9cb1809b0ce06757389b7e7cff300b540015882b39a75c6d7e8499757948`。用户随后明确反馈「点击展开收起的功能应该正常了」。该项记录为用户实机反馈通过；不将其扩大为图标获取和单项菜单操作也已通过。

## 自动采集与中性图标栏（04:09 安装）

本轮定位了两个独立问题：区域截图会将半点坐标向外取整，按未取整尺寸校验会拒绝有效图像；macOS 27 的 host `AXButton` 与原应用 `AXMenuBarItem` 不一定 `CFEqual`，优先 host 镜像会令系统命中检查失败。现优先使用原应用身份，严格宿主关联仅在身份关系可证明时使用；不能证明关联时，必须重新命中原身份自己的实际位置，而不是按 PID 或横坐标猜配。

- 启动及刷新在录屏已授权时自动准备系统溢出区，采集后恢复本次主动打开的入口。本机日志确认自动打开与 `restored=true`。
- 04:09 本地安装包实际采得 19 个经过命中校验的图像，采后再次校验仍为 19，丢弃 0。随后展开独立面板，AX 与截图均显示当前 13 个隐藏项，未出现缺图占位符。该计数只代表此次运行中的项目，不代表此前不同版本的十四项配置。
- 图像仅在内存中处理。统一背景可靠时去除截图底色，黑白图案使用透明模板适配明暗，彩色图案保留前景颜色。原图背景无法可靠识别时仍保留原图。与背景完全同色的前景无法单凭截图区分，此方法不是对任意壁纸的无损分层恢复。
- 首次设计安装仍有一项因图案贴边保留绿色矩形；补充三边及角点证据后，04:09 的最终面板截图中当前 13 项的绿色底块均已消失，彩色角标仍在。面板使用中性实色、44 点点击范围、22 点以内等比图案、悬停反馈和简短页脚。

## 隐藏项点击跳到本应用设置（04:32 起实测）

根因包含两层：旧单项流程在原生分隔项仍收起时先验证移动位置，无法得到有效几何；普通失败分支随后主动打开本应用设置。另经本机实测，直接向隐藏的原 AX 对象发送一次 AXPress 返回成功，并不保证目标菜单出现。

修复流程临时缩短边界并准备 overflow，保存原分组及紧邻右项，把目标移到控制按钮左侧的可见位置，再收起其他图标，只发送一次经过身份、位置、命中和输入检查的鼠标点击。关闭目标展示后，在独立恢复任务中验证恢复原分组和原右邻项。普通错误留在图标栏；仍有待恢复操作时提供右键重试及详情入口，不自动抢走目标界面的焦点。

统一进程启动时间检查：系统后台应用未提供 `NSRunningApplication.launchDate` 时，与扫描路径一致读取内核进程启动时间，仍检查 PID、bundle 和进程生命周期。操作错误与截图错误分别保存，图像刷新不再覆盖点击失败原因。
