# 新启动隐藏应用的托盘发现修复

日期：2026-11-10。基线：`fa9a4b44a1235da43a42631ca32615720a4b1f44`，原安装公开版本 `0.7.7 / 83`。先发布 `0.7.8 / 84`，再补齐通知缺口并发布 `0.7.9 / 85`；均按用户授权先提交推送发布，再通过本机应用内更新升级。0.7.9 已完成下述实机验收，发布源码为 `b74c146f09f0804304c1b932101f4e09d9b609fa`。

## 复现与原因

在 macOS 27.0.1（26A434）/ arm64，先退出 Maccy，再正常退出并启动 Menu Tidy，保留 Maccy 的“收起后隐藏”分类。随后启动 Maccy，手动刷新仍未进入列表。只读来源观察能确认 Maccy 当前进程及其图标存在，来源坐标在屏幕外。

原生 assessment 隐藏按应用 bundle 工作，也覆盖当前未运行但保留分类的应用。该应用后来启动时，菜单栏来源已被原生后端隐藏。原扫描器要求来源具有菜单栏内坐标或已验证的宿主绑定，因此过滤了新进程的来源；旧进程的隐藏图标保留路径无法帮助首次出现的新进程。重启 Menu Tidy 会先释放隐藏，因而暂时绕开问题。

另一个时序缺口是应用启动通知只安排一次扫描，而状态图标可能晚于启动通知才创建。

## 修复

- 只有调用方确认仍由本应用原生后端管理且处于隐藏状态的非系统应用，才允许身份发现。
- 来源必须是自身 `AXExtrasMenuBar` 根下的直接 `AXMenuBarItem`，根 PID 与来源 PID 相同，进程启动时间有效。宿主镜像、嵌套控件、普通菜单内容、系统应用和未知进程均不获此例外。
- 没有可用坐标的来源仅提供身份；`hasReliableGeometry=false`，不推断物理隐藏，也不能使用该坐标点击或验证位置。打开菜单仍走原有临时显示、当前进程及新几何证明。
- 按 PID、bundle 和启动代次安排启动后的只读重试，截止点为识别启动后的 1、3、7、15 秒。0.7.9 同时使用运行应用列表成员变化与启动通知。成功发现或进程退出后移除，长暂停合并过期尝试，不补发积压读取。已有图标操作期间不开始扫描。
- 自动分类仍使用既有的每进程一次连接规则，发现重试不会重放失败的分类或原生点击。

## 0.7.8 发布后发现的通知缺口

`ec34758b93d4652524547a3b308c64922833d7c7` 已发布 v0.7.8 / 84，经 Sparkle 应用内更新安装。双架构 CI、八项公开附件、归档与 feed EdDSA、代码签名和本机二进制摘要已验证，三项分类偏好语义相等，草稿为零。首次升级因本机 HTTP 缓存仍返回 build 83，正常退出并确认恢复日志已清空后，将本应用缓存移至本地证据目录保留；未修改分类偏好。

首次“Menu Tidy 先启动、随后启动 Maccy”自动接回，但时间与启动后 30 秒补偿重合，不能证明启动通知路径。后续重启 Maccy，50 秒后仍未自动接回；手动刷新立即接回，无需重启 Menu Tidy，说明来源过滤已修复而触发路径仍有缺口。

独立只读观察同时订阅工作区启动/退出通知、观察 `runningApplications` 成员变化，并核对运行列表。18:17:30 Maccy 退出、18:17:39 新 PID 21269 启动，成员观察均收到变化；同一观察程序没有收到启动/退出通知。这是在本机 CUA 启动后台应用路径的实测，不推广为所有启动方式都会丢失通知。

0.7.9 增加运行列表成员观察，保存首次列表作为基线，对新增进程安排现有有限读取；按进程代次去重，并在退出或停机时清理。已有通知路径保留。新增集成测试覆盖无启动通知、成员不变不重试、重启后新一轮重试及初始列表不触发。

0.7.9 完整本地检查通过：109 项 Python、529 项核心 Swift、151 项应用集成测试，warnings-as-errors 构建与源码、本地化检查通过。
