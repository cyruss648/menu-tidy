# 新启动隐藏应用的托盘发现修复

日期：2026-11-10。基线：`fa9a4b44a1235da43a42631ca32615720a4b1f44`，已安装公开版本 `0.7.7 / 83`。本轮准备 `0.7.8 / 84`；按用户授权先提交推送发布，再通过本机应用内更新升级，最后验收。

## 复现与原因

在 macOS 27.0.1（26A434）/ arm64，先退出 Maccy，再正常退出并启动 Menu Tidy，保留 Maccy 的“收起后隐藏”分类。随后启动 Maccy，手动刷新仍未进入列表。只读来源观察能确认 Maccy 当前进程及其图标存在，来源坐标在屏幕外。

原生 assessment 隐藏按应用 bundle 工作，也覆盖当前未运行但保留分类的应用。该应用后来启动时，菜单栏来源已被原生后端隐藏。原扫描器要求来源具有菜单栏内坐标或已验证的宿主绑定，因此过滤了新进程的来源；旧进程的隐藏图标保留路径无法帮助首次出现的新进程。重启 Menu Tidy 会先释放隐藏，因而暂时绕开问题。

另一个时序缺口是应用启动通知只安排一次扫描，而状态图标可能晚于启动通知才创建。

## 修复

- 只有调用方确认仍由本应用原生后端管理且处于隐藏状态的非系统应用，才允许身份发现。
- 来源必须是自身 `AXExtrasMenuBar` 根下的直接 `AXMenuBarItem`，根 PID 与来源 PID 相同，进程启动时间有效。宿主镜像、嵌套控件、普通菜单内容、系统应用和未知进程均不获此例外。
- 没有可用坐标的来源仅提供身份；`hasReliableGeometry=false`，不推断物理隐藏，也不能使用该坐标点击或验证位置。打开菜单仍走原有临时显示、当前进程及新几何证明。
- 按 PID、bundle 和启动代次安排启动后的只读重试，截止点为启动通知后的 1、3、7、15 秒。成功发现或进程退出后移除，长暂停合并过期尝试，不补发积压读取。已有图标操作期间不开始扫描。
- 自动分类仍使用既有的每进程一次连接规则，发现重试不会重放失败的分类或原生点击。
