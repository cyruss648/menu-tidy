# 托盘菜单锁屏中断修复记录

日期：2026-10-16。源码基线：`983b76c`，公开版 `0.6.14 / build 70`。本记录区分本地修复、隔离测试与真实桌面结果。本轮准备发布 `0.6.15 / build 71`；下文保留 `0.6.14 / build 70` 候选包的真实验证过程，公开发布状态以 GitHub Release 与已签名更新 feed 为准。

## 现场现象与原因

用户从托盘打开 BLEUnlock 原生菜单，选择“立即锁屏”，解锁后管理窗口显示 `Swift.CancellationError`，并以“请先完成图标恢复，再应用分类”禁用分类操作。现场展开恢复详情后确认了该错误；操作日志中，菜单展示成功、桌面暂停、恢复后的刷新仍标记 `recoveryPending=true` 相互对应。

前一版只对扫描、分类和补偿做了桌面会话隔离。托盘激活任务在会话暂停时被取消，但随后的独立清理任务继续查询旧菜单是否关闭，并尝试核验隐藏。核验检查发现桌面不可用，抛出正常的取消；通用错误分支却清除了图标确认信息、设置持久的恢复错误。解锁后的刷新无法清除它，自动补偿也被此错误阻止。

同一路径还存在两种相关情况：旧的菜单展示结果可能在快速锁屏和解锁后继续发布；菜单关闭观察可能在锁屏后继续执行。它们不应触发重放菜单命令，也不应被标为应用分类失败。

## 修复行为

- 托盘原生操作和应用窗口操作记录开始时的会话代次，在异步返回后核对；跨会话结果停止发布。锁屏时不能打开托盘或发出原生菜单动作。
- 发生会话中断后，停止查询旧菜单，把临时显示目标的身份保留为待恢复项；原有原生恢复账本继续保留确切的设置所有权。
- 解锁后沿用现有两秒稳定窗口和一次刷新。在恢复补偿前，用新列表确认原进程与来源身份，条件恢复隐藏并重新核验，不重复调用第三方菜单动作。
- 恢复核验中再次锁屏时，保留待恢复项到下一次解锁。来源或进程已变化时，只按账本恢复原始设置，不能沿用旧菜单的确认信息。
- 真正的设置冲突或恢复失败继续显示错误并保留手动恢复入口。手动恢复成功后清除相应的会话等待状态，避免残留阻塞。
- 用户实测发现解锁后第一次点击没有响应：托盘显示阻止恢复，而未完成恢复又阻止图标激活。修正后，托盘打开不再阻止这次恢复。恢复期间接受一个新的用户点击并显示等待状态，恢复和身份核验成功后执行一次；连续点击合并、收起托盘取消、重新锁屏取消，恢复失败或进程变化不能继续发送动作。后台分类补偿仍等待托盘关闭，但不重复已成功的恢复刷新。
- 图像统计继续按真实来源核验图片，但“本次未确认”的数量改用已协调的离线记录；不把在线应用的旧来源重复计入，也不漏掉仅有原生显示选择的离线应用。

图像快照缺失与分类失败是不同状态。没有可确认的原始快照时，托盘仍可显示带名称的应用图标。离线记录保留用户选择，不因本轮没有读取到来源而删除。

新增的 9 项托盘会话集成测试覆盖：锁屏时拒绝操作、原生菜单触发锁屏、快速锁屏和解锁、正常关闭菜单、恢复验证中锁屏、解锁恢复中再次锁屏、真实恢复失败、显式恢复解除阻塞，以及原进程重启。测试驱动真实模型的托盘激活和清理流程，系统边界使用内存替代，不查询或修改用户菜单栏。修复前的回归运行有 8 个断言失败，相关日志保留于本地。

首击修复另增 9 项回归：保持托盘打开恢复、立即首击、恢复刷新中的点击、连续点击合并、收起取消、失败禁止发送、进程变化、过期恢复不能消费新会话点击，以及后台补偿不重复刷新；部分行为在同一测试内验证。扫描失败时显示明确的恢复入口，结束等待状态，手动恢复成功后解除阻塞。

另有 2 项图像统计回归，覆盖在线应用来源替换和没有旧来源规则的离线原生选择。既有会话、原生批量、增量扫描、界面布局和安装回滚测试一并通过。
