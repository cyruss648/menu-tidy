# Atoll 原生隐藏与重复草稿验证

本记录对应 0.6.12 / build 68，验证日期为 2026-10-15，设备为 macOS 27.0.1 Apple Silicon。提交前使用既有发行身份签名的候选包，在 `/Applications/Menu Tidy.app` 和用户现有偏好中验证。双架构 CI、公开包、Sparkle feed 和公开版本安装按发布流程独立核验，本文记录提交前已取得的证据。

## 为什么一行 Atoll 对应两条草稿

0.6.11 已按应用共用的原生显示开关合并设置行。实机基线保存的 Atoll 草稿来自两个源节点：一个是 `AtollNotch` 标识的“计时器”，另一个是真实状态项的会话来源。界面合并为一行，但待处理计数仍按原始来源累加，所以出现一行应用、两条待处理。

Atoll 自身的辅助功能树表明，“计时器”是刘海浮窗中 `AXSystemDialog` 下的 `AXImage` 和文本，并非状态项。系统菜单栏宿主还投影了这个普通远程窗口，扫描只凭标识、标签和菜单栏附近的几何位置接受了其子节点。原生显示开关会影响真实状态项，却无法让刘海窗口满足状态项的正向隐藏证明，因而整次分类回退并保留失败草稿。

## 修复合同

扫描宿主窗口时，仅在角色读取、进程归属和宿主关系已确认后，停止遍历普通远程窗口、对话框、sheet、popover 和 drawer。宿主自己的展示窗口、真实 `AXMenuBarItem` 和未知读取结果沿用现有处理。扫描记录本轮排除的准确窗口对象；旧来源只有在父链与该对象精确匹配时才停止延续，未知父链不会被当成图标消失。

原生路径的待处理、重试和可操作数量按设置行的展示身份统计。实际操作队列、来源身份和逐项验证保留原有范围，系统模块不因宿主相同而共用隐藏权限。

只有当前全部真实来源均具有当前进程生命周期、正向原生可见性证据、已应用分类和匹配规则，且保存的应用选择仍一致，才消费相同完整 bundle identifier、相同分类的旧草稿。这包括旧会话和曾被误识别的窗口来源，但不把旧 ID 重新绑定为当前图标。不同分类、其他应用及未确认失败继续保留。未发现图标、仅保存选择或接口调用返回都不足以触发清理。

## 自动回归

`./scripts/check.sh --full` 通过 96 项 Python、504 项核心 Swift、53 项应用集成测试，编译启用 warnings-as-errors。

- 窗口策略覆盖 Atoll 对话框子树排除、合法宿主状态项和系统模块保留、未知归属/角色及根窗口保护。
- 草稿存储覆盖同分类旧来源消费、完整应用身份与保存选择检查、已验证会话备份不再复活，以及不同分类和其他应用记录保留。
- 真实应用模型的隔离集成测试覆盖原生成功、可见性确认失败、完整重启和旧草稿迁移。失败时保留两条原始草稿的 UUID 与内容，回退可见性，并以一行应用计算重试和待处理数。
- 多来源失败测试同时核验应用全部、重试、未完成和可操作计数均为 1；底层仍有两个失败来源。

## 提交前实机结果

| 验证 | 结果 |
| --- | --- |
| Atoll 恢复常驻显示 | 界面确认 1 项，日志 `classificationConfirmed=true hidden=false itemCount=1` |
| Atoll 改为收起后隐藏 | 界面确认 1 项，日志 `classificationConfirmed=true hidden=true itemCount=1` |
| 独立托盘 | 22 个图标，其中 Atoll 仅一个入口 |
| 稳定状态连续三轮刷新 | 每轮搜索结果一行、计数 1，无新失败或待处理 |
| 关闭并重开管理窗口 | 一行 Atoll，保留收起后隐藏，无待处理 |
| 正常退出并完整进程重启 | 当前真实图标重新确认；搜索仍一行，无新草稿 |
| 原两条草稿的启动迁移 | 应用停止时重新放回最初保存的两条记录；候选启动确认后自动消除，持久化记录为 0 |
| Atoll 刘海窗口 | 隐藏状态项后仍可读取原计时器窗口和 `AtollNotch`，未操作其活动内容 |

宿主扫描日志确认排除 Atoll 的远程 `AXWindow`，包含准确 owner PID、宿主 PID 和深度。单项显示/隐藏及三轮刷新均记录 `failed=false recoveryPending=false`。窗口角色在宿主投影和应用自身树中可以不同，排除依赖已确认的远程窗口边界，不依赖 Atoll 名称或特定计时器标识。

两条旧草稿在先前正常退出和安装之间已不再出现在即时偏好中，因此迁移验证单独重新放回最初捕获的确切两条记录，在候选完整启动后核验自动消费，避免把安装前的零记录冒充迁移成功。未手工删除草稿来制造通过。结束时原生应用分类与基线一致，规则与安装前解析值一致，草稿为 0。正常退出后进程及四类恢复 journal 均不存在。

候选签名 designated requirement 与既有发行证书一致；安装前保留旧应用备份，替换时解析偏好值保持一致。个人偏好、完整 AX 树和诊断日志保留在忽略的本地目录，未纳入源码。

## 验证边界

本次实机确认的是 Atoll 状态项的原生显示/隐藏和相应草稿迁移。刘海浮窗本身继续由 Atoll 管理。其他第三方浮窗、Intel 桌面、旧版 macOS、全屏和 Space 切换未完成本次设备验收，双架构构建不能代替这些运行验证。发行签名沿用项目自签名身份，未经过 Apple 公证。
