# Menu Tidy 0.4.1 自动分组修复记录

修复版本为 **0.4.1 / build 11**。本文记录 0.4.0 自动应用分组的实际中断证据和已实现补丁；**本地修复包已安装，完整隐藏流程和 GitHub Release 尚未完成验证**。

案例仅保留必要时序与匿名计数，不公开用户选择的应用清单、标识或偏好文件。

## 0.4.0 的实际复现

用户选择 14 项隐藏后，界面仍有多项「待应用」，并处于临时显示全部状态；一次目标移动报取消。因此当时不能认定这 14 项已全部生效。

| 日志时间 | 观察 | 可得出的结论 |
| --- | --- | --- |
| 14:39 | 鼠标位置偏差使指针停靠状态失效，当前移动取消 | 确认取消路径已触发；仅此记录不能区分用户真实介入和系统事件处理延迟。 |
| 14:40:50 起 | 按用户原选择重试，8 项分别取得连续两次 `trusted-match` | 这些项目取得了移动位置验证；**不是最终 14 项全部生效或整体隐藏通过的证据**。 |
| 14:41:06.180 | 某目标第 27 个拖动事件已发送，系统事件计数仅到 26；`expectedDelta=20.666687`。没有额外鼠标移动计数，仍只有本次操作自身的 1 次 | 此次观察支持系统尚未处理完已投递事件，固定等待 14 ms 后的位置检查过早触发取消。 |
| 后续重试 | 初始扫描暂时缺少本应用定位项，操作停止 | 没有继续猜测位置或宣称全部成功；该次停止不属于完成分组。 |

## 已实现的源码补丁

以下列出代码变化，尚不作为 0.4.1 实机通过结论：

- 每步拖动在有界时间内等待系统位置到位，替代固定 14 ms 后立即据位置偏差取消的判断。
- 将真实异常输入与位置等待超时分开报告；保留用户干扰检测及合成输入释放保护。
- 全部项目成功后自动收起；失败时明确提示未全部生效，并保持展开以便恢复。
- 应用期间持续显示进度和暂勿操作鼠标、键盘的提示。
- 初始定位项暂时缺失时，最多进行 3 次只读扫描重试；仍无法确认则停止，不放宽定位保护。

## 本地修复包后续检查

- `warnings-as-errors` 编译与 **55 项核心测试**通过，新增 11 项拖动到位判定回归测试。
- 安装后核对并恢复原有 14 项选择；已确认位置的 8 项保留，剩余 6 项仍待完整应用。
- 自动应用目前在一项系统图标的点击命中检查停止：读到有效矩形，但系统点击查询没有返回匹配节点。手动展开系统溢出区后仍复现。此结果不等于拖动等待回归失败，也不允许声称完整分组已生效。
- 补充了仅失败时输出的命中链诊断，记录 PID、角色、矩形及一致性布尔值，不记录标识文本、应用名或窗口名；匹配条件没有放宽。
- 后续安装诊断包的电脑操作因系统锁定而停止，需用户手动解锁后继续。运行中的本地修复实例和待应用选择保留，尚未将诊断包替换到安装目录。
