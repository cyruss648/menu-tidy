## 已实现的源码补丁

以下列出代码变化；实际验证范围见后文，不能将实现本身当作全部流程通过：

- 每步拖动在有界时间内等待系统位置到位，替代固定 14 ms 后立即据位置偏差取消的判断。
- 将真实异常输入与位置等待超时分开报告；保留用户干扰检测及合成输入释放保护。
- 全部项目成功后自动收起；失败时明确提示未全部生效，并保持展开以便恢复。
- 应用期间持续显示进度和暂勿操作鼠标、键盘的提示。
- 初始定位项暂时缺失时，最多进行 3 次只读扫描重试；仍无法确认则停止，不放宽定位保护。

## 本地检查与 9 月 24 日实机结果

初始修复包的 `warnings-as-errors` 编译与 **55 项核心测试**通过，其中新增 11 项拖动到位判定回归测试。本地 release 包通过固定证书约束和严格签名验证；后续诊断版 `0870ee8` 已实际替换安装到 `/Applications/Menu Tidy.app`，不再处于等待安装状态。这些本地安装均不是从最终 GitHub Release 下载后的验收。

| 检查 | 实际结果 | 结论边界 |
| --- | --- | --- |
| 诊断版启动 | 发生过一次 `EXC_BAD_ACCESS`，定位到后台访问本应用自身 AX；重启后辅助功能显示已开启 | 记录了新的启动缺陷。重启成功不代表崩溃已经修复，后续修复包仍需验证。 |
| 系统图标命中失败 | 命中链与 PID 核对确认，目标位置被 Atoll 的顶层 `AXWindow` 覆盖 | 此次停止有实际遮挡依据，不能通过放宽目标命中保护来处理。 |
| 临时退出遮挡工具后应用 | 剩余六个目标各取得连续两次 `trusted-match`；界面无待应用项目，并自动显示已收起 | 证明这次无该遮挡条件下的六项目应用成功。不能据此断言原十四项全部通过。 |
| 拖动延迟恢复 | 第 27 步出现 `arrival-wait` 后继续执行，随后完成位置验证 | 实机覆盖了系统处理延迟时有界等待后继续成功的路径。真实用户干扰取消和超时安全释放仍需分别验证。 |
| 收起／展开切换 | 稳定的 MenuBarAgent AX 观察中，收起时仅保留常驻项与「···」；点击「···」后测试隐藏项出现，再次点击并等待稳定后隐藏项消失 | 取得本次测试目标的实际切换与 AX 可见性证据，不外推为所有图标、遮挡环境或显示器均通过。 |

测试后 **Atoll 已重新启动**。它在本次六项目测试时处于退出状态，因此即使界面当时没有待应用项目，也不能把两轮的八项与六项简单相加为原十四项完整通过；恢复运行后的相关图标及整体状态仍需检查。

命中诊断仅在失败时记录 PID、角色、矩形和一致性布尔值，匹配保护未放宽。公开记录保留上述归纳结果，不附用户应用清单、偏好文件或原始日志。
