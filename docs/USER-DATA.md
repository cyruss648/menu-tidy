# 用户数据与存储位置

Menu Tidy 的日常配置保存在当前 macOS 用户的偏好设置中；原始菜单栏图标快照只保存在运行中的应用内存里。macOS 27 的原生隐藏路径还会读写系统菜单栏显示设置；旧排序记录仅用于兼容与历史恢复。两条路径分别保存本次修改的私有恢复账本。开发机器上的测试备份、签名资料与这些用户配置是不同用途的数据。

本文说明当前 **0.5.0**源码的存储行为。旧版本或后续版本有差异时，以对应版本说明为准。路径中的 `~` 表示当前用户的个人文件夹，不依赖某个固定用户名。

## 日常配置

正式应用的偏好设置域为 `dev.hdh.MenuTidy`，通常对应：

```text
~/Library/Preferences/dev.hdh.MenuTidy.plist
```

应用通过 macOS 的 `UserDefaults` 读写，系统可能缓存并稍后写入文件。这个文件不是需要在应用运行时手工编辑的配置入口；日常修改应使用管理界面。

| 内容 | 相关设置键或存储方式 |
| --- | --- |
| 已保存的图标分类 | `itemRules.v1`：包含图标稳定标识、应用名称／bundle 标识和分类的编码数据 |
| 未应用的明确分类选择 | `itemDrafts.v1`：草稿 ID、目标标识及名称、bundle 标识、所选分类；不代表实际隐藏成功 |
| 应用级原生托盘选择 | `nativeTrayChoices.v1`：按精确 bundle 保存的常驻或托盘意图；同应用多个图标共用选择 |
| 原生选择解码失败备份 | `nativeTrayChoices.unreadableBackup`；原数据保留，失败时不自动重写 |
| 原生显示设置文件书签 | `nativeMenuBarVisibilityFileBookmark.v1`：精确系统偏好文件访问 |
| 草稿解码失败备份 | `itemDrafts.unreadableBackup` |
| 首次设置是否完成 | `hasCompletedSetup` |
| 启动时收起 | `startCollapsed` |
| 自动收起及等待时间 | `autoCollapse`、`autoCollapseDelay` |
| 全局快捷键开关 | `shortcutEnabled` |
| 原生「始终隐藏」区域状态 | `usesNativeAlwaysSection` |
| 管理窗口位置与尺寸 | AppKit 自动保存的 `NSWindow Frame …` 项 |
| 本应用菜单栏控制项的位置提示 | AppKit 的 `NSStatusItem Preferred Position …` 项 |
| 读取失败的旧规则备份 | 仅在规则解码失败时使用 `itemRules.unreadableBackup` 保留原数据 |
| 排序目录的访问书签 | `menuBarPositionDirectoryBookmark.v1`：通过系统文件选择器授予的精确目录访问，用于重启后恢复访问，不应作为反馈附件公开 |
| 排序布局待确认状态 | `positionLayoutReviewNeeded.v1`：写入中断或恢复尚未确认时，重启后继续提示检查，不代表分类已成功 |
| 软件更新偏好 | Sparkle 管理 `SUEnableAutomaticChecks`、`SUAutomaticallyUpdate` 等更新设置；更改后持久保存 |
| 最近检查更新时间 | Sparkle 管理 `SULastCheckTime`；网络错误不应被解读为当前已是最新版 |

并不是每个键都会立即出现在文件中。未修改的默认值可能只由应用注册，保存相关设置后才会写入。登录启动的实际状态由 macOS 管理，不以这个文件中的开关值作为唯一依据。

通过 `--demo-items` 启动的开发演示模式，主要设置使用独立的 `dev.hdh.MenuTidy.demo` 偏好设置域，通常对应 `~/Library/Preferences/dev.hdh.MenuTidy.demo.plist`。演示数据不应当作正式分类规则的备份；AppKit 的窗口和菜单栏位置提示仍可能使用应用自身的偏好设置域。

## 原生菜单栏显示与恢复

普通应用原生显示设置位于：

```text
~/Library/Group Containers/group.com.apple.controlcenter/Library/Preferences/group.com.apple.controlcenter.plist
```

其中 `trackedApplications` 是系统维护的应用记录。Menu Tidy 只修改精确匹配目标的 `isAllowed`，保留其他记录和字段。此文件不是本应用配置，不应为重置或卸载而删除。系统模块使用经过单独验证的设置，不按整个 MenuBarAgent 进程隐藏。

`Transactions/NativeVisibility.plist` 保存普通应用显示开关的原始目标记录、已写入状态和待完成写入；`Transactions/NativeSystemVisibility.plist` 保存支持的系统模块状态。两者均以私有权限持久化，写设置前先记意图。启动、退出和恢复时只条件恢复本应用仍拥有的修改，不用整份偏好备份覆盖外部新设置。文件缺失、损坏或冲突不视为恢复完成。

菜单展开期间临时恢复目标可见，关闭后再隐藏；无法确认菜单状态时保留恢复提示。清理或卸载前应正常退出并完成恢复，不直接删除这些账本。

## 旧系统菜单栏排序与事务备份

旧 macOS 27 排序隐藏与历史恢复路径使用以下系统偏好文件中的 `TrailingItemPreferredPositions` 位置表：

```text
~/Library/Group Containers/com.apple.MenuBar/Library/Preferences/com.apple.MenuBar.plist
```

**这份文件由 macOS 拥有，包含其他应用的菜单栏排序，不是 Menu Tidy 自身的配置文件。不要为重置或卸载 Menu Tidy 删除整份 plist，也不要清空整个位置表。** Menu Tidy 自身的分类规则、待应用草稿和开关仍保存在前述 `dev.hdh.MenuTidy` 偏好设置中。

排序访问与辅助功能、屏幕录制分别授权。应用在系统文件选择器中定位到该文件所在的 `Preferences` 目录，用户确认后保存安全作用域书签；无需完整磁盘访问权限。目录访问本身不证明图标已移动成功。

新通道只修改身份已经确认、位置表中已经存在的目标单个键；保留其他条目及原有数值，不重标整张表。写入读回只是其中一步，实际菜单栏位置还需另外验证，才能保存为已应用分类。此处说明开发实现的数据行为；普通第三方应用的后台分组仍待实际验收，不表示所有图标或系统版本均可用。

单次位置调整的事务备份和持续隐藏的恢复账本保存在以下目录：

```text
~/Library/Application Support/Menu Tidy/Transactions/
```

备份文件权限为 `0600`，仅允许当前用户读写；它只保存本次触及键的原值、新值，以及事务 ID、时间和定位信息，不复制完整系统位置表，也不包含图标截图。条件回滚只还原仍等于本次写值的目标键；外部改动或缺失键不会被猜测覆盖。备份用于故障诊断及受控恢复，不应直接用它整体覆盖系统偏好文件。

同目录下的 `ActiveJournal.plist` 是单次位置调整尚未结束的事务日志，写系统排序前保存。成功提交、完整回滚或用户明确选择保留当前布局后，结束对应日志记录；历史备份保留。

`HiddenItems.plist` 是**持续隐藏管理所必需的恢复账本，不是可随意清理的历史备份**。它保存每个受管理键的精确原始数值、隐藏值、本应用最近写入值、隐藏或临时显示状态，以及未完成写入的预期值与目标值；这些记录在对应分类已成功应用后仍然保留。每次改变系统位置前先原子保存待写意图，便于进程异常退出后区分未写入、已写入及外部冲突。账本权限同样为 `0600`，不包含图像；其中的目标键可能透露应用使用情况，不应默认作为反馈附件公开。

启动会分别读取 `ActiveJournal.plist` 和 `HiddenItems.plist`，不遍历历史备份猜测恢复操作。结束隐藏管理或正常退出时，只有系统当前值仍符合本应用记录才恢复原值并结束相应账本记录；外部修改、缺失键或无法安全读取的记录会保留恢复提示，不强行覆盖。清理数据前应先在应用中完成恢复，不能通过手动删除账本假定系统位置也已恢复。界面中明确选择保留当前布局时，只放弃相关恢复记录，不修改系统排序，也不会自动应用分类草稿。

`Transactions` 属于后台分组产生的数据，不是构建签名材料。它不会因为删除或重装 `Menu Tidy.app` 自动清除；备份中的目标标识也可能透露应用使用情况，反馈问题时无需默认上传整个目录。

## 运行时数据与图标快照

以下内容主要保留在当前应用进程中，不会作为图标缓存文件写入磁盘：

- 原始菜单栏图标图像及最近采集时间。关闭图标栏不一定清空整个内存缓存，但退出应用后缓存不再保留；重新启动后需要重新采集。
- 菜单栏扫描快照、辅助功能对象引用、当前显示状态，以及会话草稿与当前图标的临时绑定。
- 同一进程生命周期内最近确认的图标分类。它只供部分扫描时保持列表和图标栏显示，不作为移动完成的验证依据，也不写入偏好设置。
- 缺少唯一稳定标识的 `session:` 图标分类。保存规则时会排除这些项目，重新启动后不能依赖它们恢复原分类。
- 图标点击调用前后的展示基线、所关联的进程身份、短期 AX 对象和操作状态。受管理隐藏项点击时会临时调整单项排序以便操作；原始值、临时值及待恢复状态写入前述 `HiddenItems.plist`。目标界面关闭后条件恢复隐藏，状态无法确认时保留记录与恢复提示，不发送全局模拟鼠标输入。

分类界面的待应用草稿与已保存规则不同：应用只在真实分类通过验证时保存规则，既包括后台调整，也包括用户主动完成的原生拖拽分组。不支持后台移动或未确认成功的明确选择会单独保存到 `itemDrafts.v1`。重启后，有稳定标识的草稿只按唯一的原 ID 恢复；`session:` 记录保留在“待关联草稿”中，需要明确选择当前图标后才能应用，不会仅凭名称或所属应用自动重新绑定。只有实际分类验证成功后才移除对应草稿；撤销草稿不删除已应用规则。离线草稿不参与当前应用批次，也不会阻止其他可用项目。

图标画面及去底色后的显示图像只在内存中处理，不上传、不保存为截图文件，也不采集声音。当前 macOS 27 兼容路径显示最近采集的原始快照，隐藏期间不会实时更新。

应用使用 macOS 统一日志记录诊断信息，例如操作阶段、状态、计数及几何信息；日志的保存由系统管理。开发或故障排查时另外导出的日志、截图属于测试资料，并不是应用的图标磁盘缓存。

## 软件更新缓存

更新器会将下载的安装包及安装过程中使用的数据保存在磁盘缓存中。这与菜单栏图标快照不同：图标快照仍只在内存中。当前非沙盒应用的 Sparkle 缓存根目录通常为：

```text
~/Library/Caches/dev.hdh.MenuTidy/org.sparkle-project.Sparkle/
```

Sparkle 管理其中的下载与临时文件；更新进行中不要手动清空。普通应用内升级保留原有分类、草稿、事务恢复记录和偏好设置，不把更新缓存当成用户配置覆盖。检查更新会访问 GitHub，应用关闭可选的系统配置报告，不发送图标、分类或菜单内容。使用方式与验证范围见[应用内更新](AUTO-UPDATE.md)。

## 开发、测试与签名资料

进行过本地开发、安装验证或固定签名配置的机器上，可能存在：

```text
~/Library/Application Support/Menu Tidy/
```

这个目录可能包含 `Backups`、`ReleaseSigning`、`Signing`、`Update Signing`，或名称以 `Signing-incomplete-` 开头的目录。它们用于安装前备份、本地测试或构建签名，**不是日常分类规则或图标快照的存储目录**。`Update Signing` 仅供维护者保管独立的更新签名私钥，发布的应用只携带公钥。普通发布包的使用者不一定会有这些目录。

签名资料可能包含私密材料，不应作为问题附件、用户设置备份或公开仓库内容上传。本文不列出私密文件的内部位置、证书密码或密钥内容。相关开发配置见[本地签名说明](LOCAL-SIGNING.md)。

源码工作区中的 `.local/`、`dist/` 和 `.build/` 也属于开发、测试或构建产物。它们不是通过应用程序文件夹启动 Menu Tidy 时保存日常设置的位置。

## 系统管理的数据

辅助功能和屏幕录制授权由 macOS 隐私权限系统管理，登录启动由系统的登录项服务管理。删除 Menu Tidy 的偏好设置文件不等于撤销这些权限，也不等于关闭登录启动。

需要查看或调整这些状态时，使用 Menu Tidy 的权限与设置页面跳转到系统设置，并在 macOS 中完成确认。无需直接修改系统权限数据库。

## 备份、重装与卸载

将 `Menu Tidy.app` 移到废纸篓，**不会自动删除当前用户的偏好设置文件或 `Transactions` 事务备份**。因此重新安装后，之前已保存的稳定分类与偏好仍可能恢复；内存中的图标快照和会话分类不会随之恢复。系统菜单栏排序表也应继续由 macOS 管理，不应作为 Menu Tidy 的卸载残留整份删除。

如需备份设置，应先正常退出应用，再备份偏好设置。规则数据可能包含应用名称和标识，反馈问题时通常无需上传完整偏好文件。测试备份和签名材料应与用户设置分开保管。

本文仅说明存储位置与用途，不执行数据清理，也不提供一并删除偏好设置、系统授权和签名资料的批量操作。
