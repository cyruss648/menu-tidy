# Menu Tidy 0.2.3 实机验收报告

本轮环境：2026-09-23，**0.2.3 build 7**，macOS 27.0（26A428），arm64，带刘海的内置主显示器，正式安装位置 **`/Applications/Menu Tidy.app`**。管理列表读取到 **22 个真实菜单栏项目**；系统临时项目会使数量变化。

本轮已取得三类原生移动、双次可信位置验证、规则保存、重启保留，以及管理期间原生溢出区域展开与恢复的实机证据。**普通展开仍有已确认的系统空间限制，不能将结论写成全部功能通过。** 以下区分移动、保存、可见性观察和未验证场景；构建、单元测试或列表标签不代替实际显示效果。

## 实际可见性观察

以下来自应用自身延迟只读诊断：只检查已保存规则和三个本应用定位项的 live frame 与中心 hit-test，不触发扫描、拖动、分隔项修改或系统 overflow 开关。状态序号和取消机制防止把旧状态的观察归入新一次切换；日志不记录外部应用名称或标识。

| 条件 | 观察对象 | live frame（CG points） | 中心 hit-test |
| --- | --- | --- | --- |
| 系统 overflow 关闭，普通收起 `collapsed=true` | 始终隐藏目标 | `{967, 4.5, 36, 24}` | `false` |
| 系统 overflow 关闭，普通展开 `collapsed=false` | 始终隐藏目标 | `{967, 4.5, 36, 24}` | `false` |
| 普通收起 `collapsed=true` | 收起后隐藏目标 | 取得 live frame；占位坐标不作为真实物理顺序 | `false` |
| 普通展开 `collapsed=false` | 收起后隐藏目标 | 系统可见容量仍不足 | `false` |
| 最终恢复常驻显示，普通展开；日志时间 12:03:04 | 常驻显示目标 | `{1396, 4.5, 36, 24}` | `true` |
| 最终恢复常驻显示，普通收起；日志时间 12:03:50 | 常驻显示目标 | `{1396, 4.5, 36, 24}` | `true` |
| 对应诊断中的本应用入口 | 主控制项「···」 | `{1438, 4.5, 30, 24}` | `true` |

`centerHit=true` 是目标中心当时命中相应 AX 元素的证据。`centerHit=false` 只表示该中心当时未命中目标；需结合有效 frame、系统 overflow 状态和实际交互解释，不能独立证明隐私保护，也不能代替视觉检查。CUA 的 offscreen 报错及白色菜单栏截图限制了此次直接点击与截图验收。

**手动完全展开系统 overflow 会显示「始终隐藏」项目。** 这是系统提供的恢复通道；Menu Tidy 的分类不是隐私屏障，不承诺阻止系统显示或他人访问对应应用。

## macOS 27 的位置与恢复处理

早期构建读取到控制项 `(975, 4.5, 30, 24)`、两个分隔项均为 `(983, 4.5, 22, 24)`。这些重叠坐标符合系统隐藏项目的占位表现，源中心 hit-test 未通过时，安全检查在合成拖动前停止，没有保存伪成功规则。

本轮后续实现会在管理需要时展开原生 overflow，严格校验目标，再执行原生 ⌘ 拖动。扫描保守标记明显重叠的几何为不可信；分类验证重新扫描，在有界等待内要求连续两次可信位置符合规则。恢复 overflow 后无法确认位置时，保持「实际位置未知」，不会仅因未知坐标把已保存选择伪装为待应用更改。

最终常驻显示恢复的日志时间为 12:03:02：第一次仍为占位位置，未被接受；第二、三次目标位置 `{1396, 4.5, 36, 24}` 符合分类，通过验证并保存，随后系统 overflow 记录 `restored=true`。此记录同时证明本轮等待没有将未知几何误判为成功。

管理成功时，本轮已实测原生 overflow 和鼠标位置恢复。实现只应恢复由自身打开的 overflow；用户预先已打开、输入介入、授权撤销、应用退出等分支仍需专门验收，不能由成功路径推断全部清理分支通过。

## 测试结束状态

- 测试目标 AutoFocus 已恢复为 **常驻显示**。只调整菜单栏位置与 Menu Tidy 规则，没有读取其用户数据或操作其应用功能。
- 最终 GUI 无待应用项目，显示 **22 常驻、0 隐藏**；管理界面的搜索和筛选已清除。最终偏好文件仅有一条已保存规则，`visibility=visible`。
- 已通过设置恢复 **启动时收起开启**，偏好文件确认 `startCollapsed=true`。自动收起保持关闭、全局快捷键设置保持开启、登录启动保持关闭；保留设置不代表相关功能实测通过。
- 系统 overflow 已关闭，应用以收起状态运行，主控制项中心仍可命中，无遗留测试操作。
- 恢复的是目标分类及可见性，**没有承诺原先精确像素排序**：目标由原先最左位置移动到主控制项旁。
