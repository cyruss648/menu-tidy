# 托盘原生菜单退出应用后的恢复修复

日期：2026-11-10。修改前源码基线：`f251d59949cdf91c7b6f879d67b295b22d750c11`，原资源版本 `0.7.6 / build 82`。已按用户指定顺序提交推送、发布 `0.7.7 / build 83`，通过本地应用内更新升级，并完成下述实机验收。发布提交为 `139056b9bc2beea5b5ff243948e8def6b15af949`。

## 现象与原因

用户从独立托盘打开应用原生菜单，再选择该应用的“退出”。托盘随后显示“目标界面状态暂时无法确认。图标保留可见，关闭后可重试恢复位置。”，其它图标无法打开。用户截图中的目标应用为 Maccy。

原实现先验证原进程和可访问性对象，再查询菜单是否关闭。目标进程退出使这项验证失败，菜单状态因此返回未知。模型等待三秒后设置全局位置恢复错误，保留临时显示状态；后续图标激活受该错误阻止。即使菜单已经返回关闭，清理路径仍可能尝试确认已退出图标的隐藏状态，并将来源消失记录为恢复失败。

## 修复行为

- 共享进程生命周期判断，使用原 PID、bundle identifier 和启动时间区分原进程、退出和替代进程。进程明确终止、启动代次改变或进程存在性检查返回 ESRCH 才视为退出；缺少来源、元数据不可读及其它错误不构成退出证明。
- 查询已确认的菜单或窗口前，检查其实际所属进程是否已退出。模型在异步观察前后也核对本次操作的原进程，避免退出导致的 AX 失效被当作菜单仍可能打开。
- 原进程退出后，按原生恢复账本释放本次临时显示和管理状态，不继续核验不存在的图标是否隐藏。隐藏核验途中退出也使用这条恢复路径。实际恢复失败仍保留错误和恢复记录。
- 旧位置隐藏路径仍执行条件恢复；恢复完成后，不要求已退出的原进程提供新的位置证明。恢复写入失败继续报错。
- 清除与已退出进程代次精确对应的旧图标和位置证明，保留用户分类选择，安排后续发现。重新启动的应用不能继承旧菜单操作或旧隐藏证明。
- 桌面会话中断仍沿用原有延后恢复流程。没有明确退出证据的菜单未知状态继续保留恢复保护。

## 验证

在修改前的模型上运行新增的“退出后打开另一个图标”集成测试，复现相同中文错误，第二个图标的点击次数未增加，共 11 个断言失败。恢复修复后的源码后，同一测试通过。

新增 9 项应用模型集成测试，覆盖菜单退出、菜单已关闭但来源退出、展示观察前退出、AX 操作返回时退出、隐藏核验途中退出、同 PID 新启动代次、仅 AX 来源缺失、存活进程的菜单读取失败，以及真正恢复失败时保留分类和错误。测试使用隔离偏好及内存系统接口；正常退出用例还继续打开另一个图标，确认动作执行一次并恢复其隐藏状态。

另有 4 项进程生命周期测试，检查当前真实进程、替代启动代次、已结束且被回收的真实子进程，以及无效或未知生命周期参数。
