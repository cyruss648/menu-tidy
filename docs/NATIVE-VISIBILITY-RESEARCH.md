# macOS 原生菜单栏允许开关观察

> 本文前半部分保留 9 月 26 日的历史观察；9 月 27 日已补足独立应用后台写入与图标消失／恢复证据，见文末续验。历史“尚未验证”不代表后续实现状态。

2026-09-26，macOS 27，使用 build 44 的独立只读观察器。目标为 AutoFocus（`com.mantel.AutoFocus`），通过电脑操作工具在系统设置中切换该应用的菜单栏允许开关：**开启 → 关闭 → 开启**。观察器没有创建自身菜单栏项，没有发送输入、执行 AX 动作或修改偏好。

**两轮实验确认了目标偏好记录的可逆变化、原始 AX 对象保留，以及固定展开区域内“可命中 → 不可命中 → 可命中”的受控闭环。尚无完整视觉前后对照，也未验证第三方后台调用方式；没有据此接入正式功能。**

## 本机观察到的存储结构

实际读取的是 Group Container 中的绝对偏好域：

```text
~/Library/Group Containers/group.com.apple.controlcenter/Library/Preferences/group.com.apple.controlcenter.plist
```

它不是普通 `com.apple.ControlCenter` 偏好域。以下结构来自本机快照，不能当作公开或跨版本稳定的 API 合同。

外层 `trackedApplications` 是 `Data`；再次按 plist 解码后得到交替存放键与记录的数组，而不是按应用名排列的普通记录列表。目标记录的匿名结构为：

```json
[
  {"bundle": {"_0": "<exact bundle identifier>"}},
  {
    "location": {"bundle": {"_0": "<exact bundle identifier>"}},
    "menuItemLocations": [
      {"bundle": {"_0": "<exact bundle identifier>"}}
    ],
    "isAllowed": true
  }
]
```

三份快照均包含 45 对记录。核对时先确认键与记录的 `location` 对应且无重复，再按完整结构化键比较；没有依赖数组位置、显示名称或相似字符串匹配。文档不列出其他应用。

## 第一轮：开启、关闭、恢复后的精确差异

下表时间是本地快照文件时间，用于定位证据，不等同于系统开关实际生效的精确时间。

| 快照 | 文件时间（本地） | 目标 `isAllowed` | 目标其他字段 | 其他 44 对记录 | 排序偏好整表 |
| --- | --- | --- | --- | --- | --- |
| `before44` | 20:03:41.914 | `true` | 基线 | 基线 | 基线 |
| `off44` | 20:03:59.085 | `false` | 与基线相同 | 与基线相同 | 与基线相同 |
| `on44` | 20:04:33.496 | `true` | 与基线相同 | 与基线相同 | 与基线相同 |

`before → off` 和 `off → on` 的逻辑差异都只有目标记录的 `isAllowed`。外层其他偏好字段也保持相同。恢复开启后，全部应用记录与基线在逻辑上相同。

内层数组的顺序、binary plist 编码在系统保存后发生变化，因此恢复后的 `trackedApplications` 原始字节不与基线相同；不能把这种编码差异当作其他应用设置被修改，也不能声称完成了原文件逐字节恢复。

排序表来自另一偏好域：

```text
~/Library/Group Containers/com.apple.MenuBar/Library/Preferences/com.apple.MenuBar.plist
```

三份排序快照解码后的整表相同，没有观察到本次开关操作改变排序权重。该比较不代表已找到允许开关的直接写入、通知或刷新协议。

## 第一轮：AX 对象与实际命中

观察日志包含 176 个样本，覆盖约 89 秒。全部样本都有唯一且同生命周期的目标进程；两次完整的 canonical `AXExtrasMenuBar` 子项读取一致，目标子项数始终为 1，extras 对象及原始目标对象始终保持 `CFEqual` 连续性。原始对象始终在当前子项中，位置和尺寸读取成功，单个样本内的前后矩形稳定。

因此，**系统设置关闭开关时，该应用的原始 AX 菜单栏对象没有从此接口消失**。仅通过对象存在、正尺寸或 AX 子项数量，不能判断图标是否实际展示。

| 样本范围 | 原始矩形（CG 点） | 中心命中结果 | 对应观察 |
| --- | --- | --- | --- |
| 1–111 | `[974, 4.5, 36, 24]` | `false` | 包含初始开启、关闭及恢复开启后的部分时间 |
| 112 | `[716, 4.5, 36, 24]` | `false` | 矩形转换过程中的一次样本 |
| 113–129 | `[716, 4.5, 36, 24]` | `true`，共 17 次 | elapsed 57.032–65.166 秒；恢复开启后，电脑操作工具展开了系统溢出区域 |
| 130–176 | `[974, 4.5, 36, 24]` | `false` | 系统溢出区域收起后 |

本轮电脑操作记录为约 20:04:39 展开系统溢出区域、20:04:48 收起，与上述正向命中窗口对应。不能将这 17 次命中归因为仅切换 `isAllowed` 的效果，也不能把日志概括为全程没有命中。

观察器的正向结果要求实际命中链包含保留的原始 AX 对象，并重新读取同一矩形。`centerHit=false` 仅表示此次源矩形中心没有命中原对象，不单独构成隐藏证明；AX 通信失败或无法完成的读取保留为未知。窗口截图没有提供覆盖整个目标区域的可靠前后对照，因此也没有补足物理隐藏证据。

## 第二轮：固定展开区域的受控命中闭环

为消除第一轮的溢出开关干扰，电脑操作工具在 **20:07:02 先展开系统溢出区域**，随后启动独立观察器。期间仅切换目标的允许开关：约 **20:07:17 关闭、20:07:30 开启**。观察器结束后才在 **20:08:46 收起溢出区域**，因此收起动作不在本轮采样窗口内。

第二份日志也完整结束，共 176 个样本。所有样本的目标源矩形始终为 `[716, 4.5, 36, 24]`；原始源对象与 extras 对象持续相同，唯一 owner 生命周期未变，完整子项枚举始终为 1，源对象始终在当前子项中，位置与尺寸 AX 错误均为 0，单样本前后矩形始终稳定。

| 原生开关阶段 | 样本 | elapsed 秒 | 原始对象中心命中 |
| --- | --- | --- | --- |
| 初始开启 | 1–21 | 0.009–10.206 | 全部 `true` |
| 关闭后 | 22–46 | 10.714–22.923 | 全部 `false` |
| 恢复开启后 | 47–176 | 23.432–89.003 | 全部 `true` |

对应快照为 `expandedbefore`（20:07:11.969）、`expandedoff`（20:07:22.384）、`expandedon`（20:07:34.746）。按相同结构化键重新比较，两次状态变化仍只有目标记录的 `isAllowed`，分别为 `true → false → true`；目标其余字段、其他应用记录、外层其他字段和排序整表相同，恢复开启后的全部逻辑记录与基线相同。

这轮提供了**固定原生区域内与允许开关对应的可操作性变化证据**，比第一轮排除了更多布局干扰：关闭时原对象不再接收源矩形中心的命中，重新开启后同一原对象恢复命中。它同时再次证明：关闭允许开关并不会使原始 AX 对象或其正尺寸矩形消失。

仍须保持证据范围：此处没有完整目标区域的像素截图对照，不能把命中闭环扩大为所有应用都能可靠视觉隐藏；操作来自系统设置界面，也不证明直接写入 `trackedApplications` 后会得到相同结果。

## 证据边界与后续验证

已确认：原生开关改变了一个精确目标记录；关闭后原始 AX 对象仍在；第二轮固定展开区域内取得开启、关闭、再开启的同源命中闭环；两轮结束时目标设置均恢复为开启，其他逻辑记录和排序表与各自基线一致。

仍未确认：完整视觉对照和其他应用行为；原生开关是否支持第三方后台调用；正确的通知、缓存更新、冲突恢复及跨系统版本行为。不得据此实现未经验证的偏好写入路径，或把 build 44 本轮记录当作正式隐藏功能已通过。

后续应补足固定原生区域内的完整视觉对照，并单独研究后台调用及恢复机制。未知、无法命中和被其他窗口遮挡必须与可靠隐藏结果区分；系统界面操作和拟议后台实现也必须分别验收。

原始文件仅存放在本地忽略目录 `.local/hidden-not-applied/`：第一轮为 `sep26-native-observer44.jsonl`、`sep26-native-{before44,off44,on44}.plist`、`sep26-native-{before44,off44,on44}-positions.plist`；第二轮为 `sep26-native-observer44-expanded.jsonl`、`sep26-native-expanded{before,off,on}.plist`、`sep26-native-expanded{before,off,on}-positions.plist`。这些文件包含本机偏好，仅用于本地核查，不应提交或作为发布附件。


## 2026-09-27：后台调用闭环

本轮使用独立签名测试应用创建一个红蓝色非模板菜单栏图标。只修改该测试应用的原生允许开关，不运行排序占位、系统溢出开关、模拟点击或菜单栏进程重启。在固定展开的菜单栏区域中，已取得图标出现、后台关闭后消失、自动条件恢复后重新出现的截图和宿主辅助功能树证据。第二轮仍得到相同结果。记录读回和实际显示分别检查；写入后早期截图仍可能有过渡帧，不能据此宣称立即完成。

实际调用只需要按绝对偏好域使用 `CFPreferences` 更新 `trackedApplications` 并同步。写入前重新读取完整表，按精确结构化 bundle 键找到目标，修改其 `isAllowed`，保留目标其他字段和其他所有记录。恢复前再次核对目标完整记录。测试结束时目标恢复原值，其他逻辑记录与外层字段未改变。

实际应用进程首次读取受到文件访问限制；开发终端能读不代表应用能读。通过 `NSOpenPanel` 选择上述精确 plist 文件后可读写，不需要完整磁盘访问。表内存在 `menuItemLocations` 为 `adhocBinary` 的记录；这些无关变体必须原样保留，不能因为它们与 bundle 记录格式不同而拒绝整表。生产目标仍要求归属精确，无法确认的目标不会被扩大匹配。

该原生开关按应用生效，同一应用的多个图标共用一项。应用级分类独立持久化，不再依赖旧排序表中相似的多条编号；旧位置恢复账本在启用新路径前仍须条件恢复，不能直接丢弃。

### 系统图标另行验证

普通应用的 `trackedApplications` 不适用于所有系统模块，不能把同属 MenuBarAgent 的图标按整个宿主一起隐藏。

| 目标 | 系统设置前后变化 | 独立后台验证 |
| --- | --- | --- |
| 隔空投送 | 当前用户、当前主机的 `com.apple.controlcenter` 域，整数键 `AirDrop` 的菜单栏位从 2 到 8 再到 2；掩码为 `0xA` | 单独测试应用关闭后宿主节点消失，自动恢复后重新出现；其他键和位保持相同 |
| 文字输入 | 当前用户、任意主机的 `com.apple.TextInputMenu` 域，Boolean 键 `visible` 从 true 到 false 再到 true | 独立测试应用后台关闭与 10 秒自动恢复均得到宿主节点消失／重建的证据；源不提供 AXIdentifier，尚未接入生产重绑路径 |

隔空投送的旧原生 AX 对象会在隐藏时被销毁。恢复后必须重新发现同一系统进程生命周期内、相同受保护标识的唯一新对象，不能把旧对象仍然有效作为前提。完整枚举缺失与通信失败严格区分，后者是未知状态。

### 实现约束

- 日常模式移除本应用的两项宽占位，菜单栏只保留托盘按钮；独立托盘仍是本应用面板。
- 显示设置写入成功与实际可操作性分开验证；点击时先临时恢复目标，再发送一次原生动作。目标菜单关闭后恢复隐藏。
- 写入前持久化恢复意图，恢复只处理仍匹配本应用写入的目标；外部修改保留并提示冲突。`CFPreferences` 不提供比较交换原语，最后一次核对与写入间仍有小的竞争窗口，不能声称原子隔离。
- 不启用全局 assessment-mode 允许列表；该方法会同时改变时钟、通知中心和其他系统模块行为，不符合本功能范围。
- 移除本应用制造的占位拥挤不代表屏幕空间无限。用户保留的常驻图标自身超出菜单栏空间时，macOS 仍可能显示原生溢出入口。

原始 fixture 日志、截图及偏好快照在忽略目录 `.local/native-visibility-fixture/`、`.local/system-visibility-fixture/` 和 `.local/text-input-visibility/`。这些证据包含本机应用信息，不提交到仓库。上述独立实验不代替最终 Menu Tidy 集成版本的托盘点击、退出恢复与性能验收。
