# macOS 原生菜单栏允许开关观察

2026-09-26，macOS 27，使用 build 44 的独立只读观察器。目标为 AutoFocus（`com.mantel.AutoFocus`），通过电脑操作工具在系统设置中切换该应用的菜单栏允许开关：**开启 → 关闭 → 开启**。观察器没有创建自身菜单栏项，没有发送输入、执行 AX 动作或修改偏好。

**两轮实验确认了目标偏好记录的可逆变化、原始 AX 对象保留，以及固定展开区域内“可命中 → 不可命中 → 可命中”的受控闭环。尚无完整视觉前后对照，也未验证第三方后台调用方式；没有据此接入正式功能。**

## 本机观察到的存储结构

实际读取的是 Group Container 中的绝对偏好域：

```text
~/Library/Group Containers/group.com.apple.controlcenter/Library/Preferences/group.com.apple.controlcenter.plist
```

它不是普通 `com.apple.ControlCenter` 偏好域。以下结构来自本机快照，不能当作公开或跨版本稳定的 API 合同。

外层 `trackedApplications` 是 `Data`；再次按 plist 解码后得到交替存放键与记录的数组，而不是按应用名排列的普通记录列表。目标记录的匿名结构为：

```json
[
  {"bundle": {"_0": "<exact bundle identifier>"}},
  {
    "location": {"bundle": {"_0": "<exact bundle identifier>"}},
    "menuItemLocations": [
      {"bundle": {"_0": "<exact bundle identifier>"}}
    ],
    "isAllowed": true
  }
]
```

三份快照均包含 45 对记录。核对时先确认键与记录的 `location` 对应且无重复，再按完整结构化键比较；没有依赖数组位置、显示名称或相似字符串匹配。文档不列出其他应用。

内层数组的顺序、binary plist 编码在系统保存后发生变化，因此恢复后的 `trackedApplications` 原始字节不与基线相同；不能把这种编码差异当作其他应用设置被修改，也不能声称完成了原文件逐字节恢复。

## 第一轮：AX 对象与实际命中

观察日志包含 176 个样本，覆盖约 89 秒。全部样本都有唯一且同生命周期的目标进程；两次完整的 canonical `AXExtrasMenuBar` 子项读取一致，目标子项数始终为 1，extras 对象及原始目标对象始终保持 `CFEqual` 连续性。原始对象始终在当前子项中，位置和尺寸读取成功，单个样本内的前后矩形稳定。

因此，**系统设置关闭开关时，该应用的原始 AX 菜单栏对象没有从此接口消失**。仅通过对象存在、正尺寸或 AX 子项数量，不能判断图标是否实际展示。

| --- | --- | --- | --- |
| 1–111 | `[974, 4.5, 36, 24]` | `false` | 包含初始开启、关闭及恢复开启后的部分时间 |

观察器的正向结果要求实际命中链包含保留的原始 AX 对象，并重新读取同一矩形。`centerHit=false` 仅表示此次源矩形中心没有命中原对象，不单独构成隐藏证明；AX 通信失败或无法完成的读取保留为未知。窗口截图没有提供覆盖整个目标区域的可靠前后对照，因此也没有补足物理隐藏证据。

## 第二轮：固定展开区域的受控命中闭环

为消除第一轮的溢出开关干扰，电脑操作工具在 **20:07:02 先展开系统溢出区域**，随后启动独立观察器。期间仅切换目标的允许开关：约 **20:07:17 关闭、20:07:30 开启**。观察器结束后才在 **20:08:46 收起溢出区域**，因此收起动作不在本轮采样窗口内。

第二份日志也完整结束，共 176 个样本。所有样本的目标源矩形始终为 `[716, 4.5, 36, 24]`；原始源对象与 extras 对象持续相同，唯一 owner 生命周期未变，完整子项枚举始终为 1，源对象始终在当前子项中，位置与尺寸 AX 错误均为 0，单样本前后矩形始终稳定。

| 原生开关阶段 | 样本 | elapsed 秒 | 原始对象中心命中 |
| --- | --- | --- | --- |
| 初始开启 | 1–21 | 0.009–10.206 | 全部 `true` |
| 关闭后 | 22–46 | 10.714–22.923 | 全部 `false` |
| 恢复开启后 | 47–176 | 23.432–89.003 | 全部 `true` |

对应快照为 `expandedbefore`（20:07:11.969）、`expandedoff`（20:07:22.384）、`expandedon`（20:07:34.746）。按相同结构化键重新比较，两次状态变化仍只有目标记录的 `isAllowed`，分别为 `true → false → true`；目标其余字段、其他应用记录、外层其他字段和排序整表相同，恢复开启后的全部逻辑记录与基线相同。

这轮提供了**固定原生区域内与允许开关对应的可操作性变化证据**，比第一轮排除了更多布局干扰：关闭时原对象不再接收源矩形中心的命中，重新开启后同一原对象恢复命中。它同时再次证明：关闭允许开关并不会使原始 AX 对象或其正尺寸矩形消失。

仍须保持证据范围：此处没有完整目标区域的像素截图对照，不能把命中闭环扩大为所有应用都能可靠视觉隐藏；操作来自系统设置界面，也不证明直接写入 `trackedApplications` 后会得到相同结果。

## 证据边界与后续验证

已确认：原生开关改变了一个精确目标记录；关闭后原始 AX 对象仍在；第二轮固定展开区域内取得开启、关闭、再开启的同源命中闭环；两轮结束时目标设置均恢复为开启，其他逻辑记录和排序表与各自基线一致。

仍未确认：完整视觉对照和其他应用行为；原生开关是否支持第三方后台调用；正确的通知、缓存更新、冲突恢复及跨系统版本行为。不得据此实现未经验证的偏好写入路径，或把 build 44 本轮记录当作正式隐藏功能已通过。

后续应补足固定原生区域内的完整视觉对照，并单独研究后台调用及恢复机制。未知、无法命中和被其他窗口遮挡必须与可靠隐藏结果区分；系统界面操作和拟议后台实现也必须分别验收。
