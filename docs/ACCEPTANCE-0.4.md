## 源码中已实现的行为

以下是本轮实现范围，**不是尚未执行的交互验收结果**：

- 原生整理模式显示「常隐」「收起」标记，用户按住 ⌘ 使用 macOS 原生拖动；完成动作读取实际分组，不通过合成拖动代替用户操作。
- 完成时用两次可信扫描同步能够确认的分类，未知位置不猜测；物理常隐区域按分隔项位置参与后续收起。
- 整理期间暂停列表分类、自动应用和临时显示，保留独立的完成与保持展开退出入口。退出保持已拖动位置，不声称撤销原生拖动。
- 菜单栏「临时显示全部」的调用路径不再主动打开管理窗口；结束临时显示恢复进入前的展开／收起状态。

这些修改已纳入本地与 CI 构建、测试，但系统菜单栏、窗口激活和输入行为仍需下面的真实操作验证。

## 本轮交互尝试的实际边界

- CUA 能读取 MenuBarAgent 中的本应用入口，但点击返回 `cannotClickOffscreenElement`。打开系统 overflow 后重试仍得到相同错误，未取得菜单栏入口实际点击成功的结论；本轮为排查而打开的 overflow 已收回。
- 当前 CUA 操作接口不能组合持续按住 Command 与拖动，因此没有用工具完成用户原生 ⌘ 拖动测试。
- Bartender 仍在运行，本轮未能通过 UI 暂时退出，冲突检测保持生效。因此没有分组移动结论，也没有右键临时显示或实际隐藏流程通过的结论。

上述限制记录的是本轮操作条件和工具反馈，不将其改写为 Menu Tidy 原生拖拽已经成功或已经失败。

## 已知限制与历史记录

macOS 27 的菜单栏可见容量限制仍保留：普通展开或临时显示本应用分组，不保证所有图标能同时出现在主菜单栏，必要时仍需手动系统溢出入口。「始终隐藏」不是隐私屏障；本轮没有取得这些限制已被消除的证据。

[0.2.3 实机报告](ACCEPTANCE-0.2.3.md) 中的自动分类移动与有限可见性观察属于当时版本；[0.3.1 发布与安装报告](RELEASE-0.3.1.md) 中的结果也仅对应其标签。本报告已独立记录 0.4.0 的双架构 CI、发布和 arm64 下载安装证据，但这些结果及历史报告都不替代新原生拖拽流程验收。多显示器、全屏、睡眠恢复等未覆盖场景仍需单独验证。
