## 源码中已实现的行为

以下是本轮实现范围，**不是尚未执行的交互验收结果**：

- 原生整理模式显示「常隐」「收起」标记，用户按住 ⌘ 使用 macOS 原生拖动；完成动作读取实际分组，不通过合成拖动代替用户操作。
- 完成时用两次可信扫描同步能够确认的分类，未知位置不猜测；物理常隐区域按分隔项位置参与后续收起。
- 整理期间暂停列表分类、自动应用和临时显示，保留独立的完成与保持展开退出入口。退出保持已拖动位置，不声称撤销原生拖动。
- 菜单栏「临时显示全部」的调用路径不再主动打开管理窗口；结束临时显示恢复进入前的展开／收起状态。

这些修改已纳入本地编译与核心测试，但系统菜单栏、窗口激活和输入行为仍需下面的真实操作验证。

## 已知限制与历史记录

macOS 27 的菜单栏可见容量限制仍保留：普通展开或临时显示本应用分组，不保证所有图标能同时出现在主菜单栏，必要时仍需手动系统溢出入口。「始终隐藏」不是隐私屏障；本轮没有取得这些限制已被消除的证据。

[0.2.3 实机报告](ACCEPTANCE-0.2.3.md) 中的自动分类移动与有限可见性观察属于当时版本；[0.3.1 发布与安装报告](RELEASE-0.3.1.md) 中的双架构 CI 和下载安装成功也仅对应其标签。它们不自动扩展为 0.4.0 原生拖拽流程、双架构发布或新 Release 安装通过。多显示器、全屏、睡眠恢复等未覆盖场景仍需单独验收。
