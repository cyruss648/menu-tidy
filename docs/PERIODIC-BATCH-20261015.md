# 周期补偿与批量应用

本记录对应 0.6.13 / build 69，日期为 2026-10-15。提交前在 macOS 27.0.1 Apple Silicon 上安装既有发行身份签名的候选包，使用用户现有偏好验证。公开包、双架构 CI、更新源和公开版安装按发布流程独立核验。

## 待处理为什么会再次出现

已保存的分类表示用户意图，完成状态还需要当前图标的身份、进程生命周期和真实显示结果。应用重启、图标延迟出现、系统重新投影节点或显示器布局变化后，先前结果可能需要重新确认；读取失败、缺少权限、归属冲突或原生隐藏未确认也会留下待处理。不能将这些状态一概当作菜单栏变化，也不能只因保存过分类而标记完成。

原有启动补偿在启动约 30 秒后只执行一次。初次连接也只针对同一进程生命周期尝试一次，避免短时间重复失败。因此，之后出现的新状态或同一来源的暂时失败可能继续保留到手动重试。

## 后台周期补偿

新增“后台自动应用待处理”，默认开启，每 5 分钟执行，可选择 1、5、15、30 分钟。配置保存在 `periodicApplyPending` 和 `periodicApplyPendingInterval`，无效间隔回退为 5 分钟。

周期任务复用原有单次维护 Timer、单调时钟和最近期限调度。每轮先刷新当前列表，成功后再调用与按钮相同的资格筛选。已确认、离线、归属待修复和需要单独识别的项目继续排除。执行范围不受当前搜索或筛选影响，每个目标沿用各自保存的分类。

刷新、应用、恢复、整理、原生菜单、托盘或临时显示正在使用时顺延。失败扫描不应用旧快照；应用失败保留原因和草稿，到下一个完整周期再尝试，不形成秒级重试循环。关闭开关或修改间隔会改变代次，旧刷新完成后不能触发过期周期。停止应用取消维护 Timer。启动补偿结束后重新计算周期期限，避免紧邻执行两批。

## 批处理范围

此前“应用全部待处理”逐项出队，每个应用重复进行一次完整操作和扫描。启动重连虽然共享一次操作，显示开关仍逐个写入并等待。

原生路径现在将一组普通请求固定为不可变批次，共用一次预检和一次最终扫描。同一应用的多份来源继续使用同一选择。处理中产生的新选择单独排队，旧批次完成不能覆盖它；需要单独识别的请求仍是明确的队列边界。

预检确认原有身份、进程集合、完整 bundle identifier、分类及操作支持后，普通应用的显示开关在同一偏好表中合并写入：

1. 为所有合格目标先保存各自的完整恢复记录。
2. 重新读取最新偏好，仅合并这些目标，执行最后一次竞争检查后写入一次并同步。
3. 读取结果并提交恢复账本；当前来源继续分别取得正向可见性证据。
4. 单项失败恢复该目标并保留原因，已经确认的其他目标保留。取消或全局恢复错误会等待剩余未确认目标的恢复。

`CFPreferences` 没有比较并交换接口，最终读取检查仍不能消除之后发生的外部竞争；结果不确定时继续保留恢复记录。系统模块使用独立的精确权限和偏好来源，旧版 macOS 使用兼容路径，均不强行并入普通应用的偏好写入。

## 自动回归与边界

本轮完整检查包含 509 项核心 Swift 测试、76 项应用集成测试和 96 项 Python 回归，构建启用 warnings-as-errors。

- 使用隔离偏好、虚拟单调时钟和实际维护 Timer，验证 5 分钟边界、延迟出现的应用、失败后下一周期重试、扫描失败、忙碌顺延、开关关闭、间隔变化、启动补偿合并及停止。
- 真实应用模型验证多应用只共享两次扫描，批量写入先于来源确认，单项失败、取消后整批未确认恢复、处理中产生新选择和进程重启保护。
- 真实存储实现使用内存 I/O 验证恢复日志先于偏好写入，24 个普通应用仍为一次偏好写入、两次账本保存。混合恢复/隐藏、未知字段、外部无关修改、相同目标的外部竞争、日志准备失败、对账失败、写入不确定和提交日志失败均有故障注入。
- 既有 Atoll、Clash 展示去重、草稿迁移、原生分类、托盘布局、自动收起和启动补偿回归继续执行。

## 提交前实机验收

设备为 macOS 27.0.1 Apple Silicon，使用既有发行身份签名的 0.6.13 / build 69 候选包替换本机应用，替换前保留公开版备份并核验三项偏好解析值一致。

- 启动连接真实菜单栏时，20 个普通应用合并写入一次，日志为 `batchWriteConfirmed=true targetCount=20 preferenceWrites=1`；各来源继续独立确认，界面没有未完成项。基线中 Batteries 和 FineTune 的两个常驻待确认项也已消除。
- 在应用内先正常恢复 Atoll 和 Clash 常驻，再分别选择收起后隐藏并正常取消，保留两条真实未完成草稿。此时两项均显示需处理，启动补偿和周期补偿暂时关闭，图标恢复常驻。
- 开启“后台自动应用待处理”，界面间隔为“每 5 分钟”，其间没有点击应用或重试。到期前读取界面，两项仍待处理。
- 2026-10-15 14:20:47（Asia/Shanghai）观察到真实 Timer 到期，日志给出间隔 300 秒、实际用时 300.207 秒，晚于计划期限约 0.207 秒。刷新耗时约 0.417 秒后进入 2 项应用批次。
- 两个普通应用合并写入一次，日志为 `batchWriteConfirmed=true targetCount=2 preferenceWrites=1`；两次独立隐藏确认通过，应用操作约 1.821 秒完成，`cancelled=false failed=false recoveryPending=false`。
- 界面显示“已应用并确认 2 项分类”，待处理为 0。独立托盘中 Atoll 与 Clash 各一个按钮；Atoll 刘海窗口中的原计时器仍存在，未操作其活动内容。
- 恢复原有启动补偿偏好后正常退出，确认无应用进程及四类恢复 journal。`nativeTrayChoices.v1`、`itemRules.v1`、`itemDrafts.v1` 的解析值与替换前完全一致，持久化草稿为 0。后台补偿保持开启，间隔 5 分钟。

原始取消、计时、批量写入及恢复证据保留在忽略的本地目录，未通过手工删除草稿或修改计时器时钟制造通过。已固定候选源码摘要，后续提交前核对功能代码一致。

## 验证边界

本轮已验证这台 Mac 的实际 5 分钟周期、真实普通应用批处理和相应恢复。24 应用的写入次数、取消后整批未确认恢复、外部竞争等其他故障条件仍分别以隔离测试为证。Intel 桌面、旧版 macOS、所有第三方应用和完整开机登录场景需在对应环境独立验收。双架构 CI、公开附件、更新源签名及公开版安装单独核验，不由候选测试替代。发行签名沿用项目自签名身份，未经 Apple 公证。
