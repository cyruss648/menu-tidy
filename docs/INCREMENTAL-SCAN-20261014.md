# 增量扫描重复记录回归

日期：2026-10-14。对应源码版本为 0.6.10 / build 66；公开发布状态以该标签的 GitHub Actions、Release 和签名更新 feed 为准。

## 问题与现场证据

0.6.9 的设置窗口在搜索 Clash Verge 后显示两行相同应用，行间有额外空白，列表下方存在很长的空白区域。现场搜索计数为 14，但扫描日志只记录两个不同的当前会话节点；SwiftUI 对这两个节点的 ID 明确报告 `LazyVStackLayout` 多个子视图使用相同 ID，会产生不确定结果。此次现场观察发生在旧版本，不能作为新发布包已完成安装验收的证据。

根因位于 `MenuTidyModel.scanNow` 的增量快照合并：系统菜单栏宿主的枚举结果可以归属于其他应用。上一轮快照按照归属进程未被扫描而保留，本轮经宿主再次读到相同 ID 后直接追加，造成同一 ID 重复。`rebuildRows` 把这些重复快照转换成多条记录，`ForEach` 和 `LazyVStack` 因身份冲突而出现数量、名称和布局异常。

本次没有证明两个不同宿主节点一定代表同一物理图标，也没有按应用名称、bundle、显示器位置或网速文字合并不同 ID。

## 修复

本轮 AX 扫描在内部以 ID 唯一发布当前记录。模型合并时先登记本轮 ID，保留旧快照仍须通过原有 `{ pid, bundleIdentifier, launchTime }` 生命周期校验，并且该 ID 尚未被本轮或其他保留记录发布。相同 ID 的新记录因此替换旧记录，旧列表已累积的重复 ID 也会被清除。

未扫描应用没有重新读到的不同 ID 继续保留。已扫描应用中消失的图标、退出进程、PID 重用和 bundle 变化继续使旧快照失效。读取失败仍保留上一轮成功列表，不发布失败扫描的替代结果。本次不改变图标原生操作权限、AX 身份证明、持久分类格式或图标显示选择。

## 回归验证

`Tests/MenuTidyAppTests/IncrementalScanIntegrationTests.swift` 直接运行真实模型的扫描、合并和行发布路径，仅替代枚举来源与系统读取。测试使用隔离 UserDefaults，不查询用户桌面 AX，也不投递输入事件。

- 连续七轮只扫描宿主，每轮都重新读到未直接扫描应用的两个 ID：列表始终恰为两项，最新名称可见，两个不同 ID 均保留。
- 宿主只读到同应用的其中一个 ID：该项更新，另一个有效旧 ID 保留一次。
- 直接扫描归属应用后只读到一个 ID：消失的旧图标移除。
- 归属应用退出：宿主扫描不保留其旧行。
- 同一 PID 的启动时间或 bundle 变化：旧生命周期的记录不继承。
- 宿主扫描失败：保留旧成功记录；下次成功时更新名称且不重复。
- 旧库存含 14 条重复记录，宿主只读到一个 ID：本轮观察与未观察的 ID 均各保留一次。

在合并修复前运行最初两项回归，两个测试共出现 16 次断言失败，连续扫描使两个图标增长为 4、6、8、10、12、14、16 条，并继续显示旧名称。相同测试在修复后通过；全部七项专项回归通过。

本地 `./scripts/check.sh --full` 通过 96 项 Python 回归、492 项核心 Swift 测试和 41 项应用集成测试，warnings-as-errors 编译通过。修复前失败日志、修复后专项日志和完整门禁日志分别保存在不入库的 `.local/release-v0.6.10/`。

双架构构建与公开产物验证结果由本次发布记录分别确认。本文件不把应用模型回归、旧版现场观察或 CI 构建通过写成新发布包的真实第三方菜单栏、旧版 macOS、Intel 桌面或全部多显示器场景已验收。
