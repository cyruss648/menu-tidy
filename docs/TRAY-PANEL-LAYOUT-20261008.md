# 托盘首次布局验证（2026-10-08）

用户报告托盘展开后只显示部分图标，移动鼠标后才恢复完整。此次修改只涉及独立托盘窗口的测量、布局和刷新。

## 修复前证据

在 Apple Silicon、macOS 27.0.1（26A434）、Swift 6.4 上，通过隔离偏好与内存菜单栏数据，直接创建真实 `NSPanel` 和 `NSHostingView`。19 个图标的完整内容高度为 255 点，初始窗口估算为 253 点；首次内容布局出现 90 点高度，连续展开测试也观察到窗口缩为 90 点。空托盘的内容需要 145 点，初始窗口仅有 103 点，后续曾缩为 90 点。

修复前新增的 5 项窗口布局测试全部失败，共 25 个失败断言。原始结果保存在忽略目录 `.local/panel-layout-20261008/baseline-tests.log`。

## 实现

- 控制器先保存窗口引用，再挂载 SwiftUI 视图；显示前同步完成布局并读取实际 `fittingSize`，包含空态和操作提示。
- Hosting 仅保留 `.intrinsicContentSize` 测量，窗口高度由控制器管理。[Apple 的尺寸策略文档](https://developer.apple.com/documentation/swiftui/nshostingview/sizingoptions)说明默认策略还会根据内容更新窗口的最小和最大尺寸。
- 拒绝零、负数和非有限高度。后续几何通知与模型变化合并到下一轮主线程，根据当前内容重新测量，避免在 SwiftUI 布局过程中嵌套调整窗口。
- 关闭时取消订阅和未执行的尺寸任务；展示令牌防止旧窗口回调修改新窗口。
- 非空网格外的固定高度统一为 61 点，19 项四行网格为 194 点，总高 255 点。超过四行继续使用滚动网格。

## 验证范围

[窗口布局集成测试](../Tests/MenuTidyAppTests/HiddenItemsPanelLayoutIntegrationTests.swift)直接验证真实 AppKit 窗口的首次尺寸、内容实际需求、后续自动更新和顶部锚点。测试全程不投递鼠标事件，不读取或改动用户的菜单栏分类，不申请系统权限。

新增 7 项测试覆盖 19 项首次展开、空态、31 项的四行滚动视口、连续展开、错误提示出现与清除、图标数量 `19 → 1 → 19`，以及旧窗口排队更新对新窗口的隔离。数量恢复测试先显式确认隔离数据的连接状态，再核对无提示时的高度；待连接提示本身可以合法增加窗口高度。

最终 `./scripts/check.sh --full` 通过源码检查、96 项 Python 回归、Swift warnings-as-errors 构建和全部 519 项 Swift 测试（492 项核心测试、27 项应用集成测试），无失败或跳过。完整结果保存在 `.local/panel-layout-20261008/full-check-final.log`；独立代码审阅未发现阻断问题。

源码验证与隔离窗口验证不代表已安装程序已经更新。本轮未替换 `/Applications/Menu Tidy.app`，也未发布新版本；第三方原生菜单操作、多显示器、旧版 macOS 与 Intel 桌面交互仍需各自验收。
