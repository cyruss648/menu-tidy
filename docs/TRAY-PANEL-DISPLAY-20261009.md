# 托盘多显示器定位验证（2026-10-09）

用户使用外接显示器作为主屏，在内置副屏点击菜单栏箭头时，独立托盘出现在主屏。本次修改使箭头打开的托盘优先使用本次激活时的鼠标屏幕位置。

## 原因与修复

此前打开托盘只使用扫描得到的 `menu-tidy-toggle` 位置，没有将点击所在屏幕传入窗口控制器。远程托管的菜单栏控制项及扫描结果不能代替当前点击位置。另外，扫描中的 AX/Quartz 坐标从主屏左上向下计量，窗口布局使用 AppKit 坐标；此前将两者直接混用。

- 箭头激活时读取 `NSEvent.mouseLocation`，在窗口显示和焦点改变前，将位置传入模型与托盘控制器。[Apple 文档](https://developer.apple.com/documentation/appkit/nsevent/mouselocation)说明该值使用屏幕坐标，并独立于当前事件或待处理事件。
- 根据点击点选择屏幕并计算水平锚点，在该屏幕内保留边距；优先级高于扫描得到的箭头位置及当前主窗口所在屏幕。
- 没有点击位置的入口使用可信扫描位置，并先按主屏坐标原点转换为 AppKit 坐标。无效、零尺寸及屏幕外位置不用于锚定。
- 后续尺寸更新继续使用本次展示选择的屏幕，保持顶部位置。

## 验证

本机为 Apple Silicon、macOS 27.0.1（26A434）、Swift 6.4。测试实际检测到外接主屏 `(0, 0, 1920, 1080)` 和内置副屏 `(1920, 0, 1728, 1117)`。

[真实窗口集成测试](../Tests/MenuTidyAppTests/HiddenItemsPanelLayoutIntegrationTests.swift)使用隔离偏好与菜单栏数据，直接显示真实 `NSPanel` 与 `NSHostingView`，将点击坐标指向一块屏幕、箭头锚点指向另一块屏幕。新增两项测试验证两块屏幕分别展开、窗口位于点击处下方、副屏边缘防越界，以及内容变高后仍留在副屏并保持顶部锚点。修复前两项测试共出现 11 个失败断言，修复后全部通过。

[定位逻辑测试](../Tests/MenuTidyAppTests/HiddenItemsPanelPlacementTests.swift)新增五项测试，覆盖副屏位于主屏右侧、左侧、上方和下方，主屏点击覆盖副屏锚点，Quartz 坐标转换，没有点击位置时的回退，以及无效几何。

`./scripts/check.sh --full` 通过源码检查、96 项 Python 回归、Swift warnings-as-errors 构建和全部 526 项 Swift 测试（492 项核心测试、34 项应用集成测试），无失败或跳过。托盘相关 14 项测试也单独通过。日志保存在忽略目录 `.local/panel-display-20261009/`。

## 验证边界

真实窗口测试证明这两块连接屏幕上的窗口选择、布局与动态尺寸更新；测试不投递鼠标事件，不操作用户菜单栏分类，不验证已安装应用的物理箭头点击或第三方原生菜单。左侧、上下排列由确定性几何测试覆盖，未改变用户的显示器布局。Intel、旧版 macOS、全屏与不同 Space 的交互仍需分别验收。
